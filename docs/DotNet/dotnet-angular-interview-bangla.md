## ২. C# Fundamentals

### Q23. 🟢 .NET, .NET Framework, .NET Core ও C# এর পার্থক্য কী?
**উত্তর:**
- **C#** — একটা programming language।
- **.NET Framework** — পুরনো, শুধু Windows এ চলে (শেষ version 4.8.x)। এখন শুধু maintenance।
- **.NET Core** — নতুন, cross-platform (Windows/Linux/Mac), open-source, দ্রুত।
- **.NET 5/6/7/8/9** — .NET Core এরই পরবর্তী নাম, এখন একটাই unified ".NET"। নতুন project সবসময় latest LTS (যেমন .NET 8) এ।

### Q24. 🟢 CLR, CTS, CLS, JIT কী?
**উত্তর:**
- **CLR (Common Language Runtime):** .NET এর execution engine — memory management, garbage collection, exception handling, security সামলায়।
- **CTS (Common Type System):** সব .NET language এর type কীভাবে define হবে তার নিয়ম।
- **CLS (Common Language Specification):** CTS এর একটা subset — যা মানলে এক language এর code অন্য language থেকে ব্যবহার করা যায়।
- **JIT (Just-In-Time compiler):** C# code প্রথমে IL (Intermediate Language) এ compile হয়, run-time এ JIT সেটাকে machine code এ রূপান্তর করে।

### Q25. 🟢 Value type আর Reference type এর পার্থক্য কী?
**উত্তর:**
| Value type | Reference type |
|---|---|
| `int`, `double`, `bool`, `char`, `struct`, `enum` | `class`, `string`, `array`, `interface`, `delegate` |
| সাধারণত stack এ থাকে | heap এ থাকে, stack এ শুধু reference |
| Assign করলে copy হয় | Assign করলে একই object এর reference copy হয় |
| default null হতে পারে না (`int?` ছাড়া) | null হতে পারে |

```csharp
int a = 5; int b = a; b = 10;       // a এখনো 5
var p1 = new Person(); var p2 = p1;
p2.Name = "Rahim";                   // p1.Name ও "Rahim"
```

### Q26. 🟢 Boxing ও Unboxing কী?
**উত্তর:** Value type কে `object` (reference type) এ রূপান্তর = **Boxing**; ফিরিয়ে আনা = **Unboxing**।
```csharp
int i = 10;
object o = i;      // boxing (heap এ নতুন object)
int j = (int)o;    // unboxing
```
এটা performance এ খরচ বাড়ায়, তাই `ArrayList` এর বদলে generic `List<int>` ব্যবহার করা হয়।

### Q27. 🟢 `string` আর `StringBuilder` এর পার্থক্য কী?
**উত্তর:** `string` **immutable** — প্রতিবার পরিবর্তনে নতুন object তৈরি হয়। `StringBuilder` **mutable** — একই buffer এ পরিবর্তন হয়। Loop এর মধ্যে অনেকবার string জোড়া লাগালে `StringBuilder` ব্যবহার করুন।
```csharp
var sb = new StringBuilder();
for (int i = 0; i < 1000; i++) sb.Append(i).Append(',');
string result = sb.ToString();
```

### Q28. 🟢 `const` আর `readonly` এর পার্থক্য?
**উত্তর:** `const` এর মান compile-time এ ঠিক হয়, declaration এর সময়ই দিতে হয়, implicitly static। `readonly` এর মান run-time এ declaration বা constructor এ দেওয়া যায়, প্রতিটা instance এ আলাদা হতে পারে।
```csharp
public const double VatRate = 0.15;
public readonly DateTime CreatedAt;
public Invoice() { CreatedAt = DateTime.Now; }
```

### Q29. 🟢 `ref`, `out` ও `in` keyword এর পার্থক্য?
**উত্তর:**
- `ref` — পাঠানোর আগে variable initialize থাকতে হবে, method পরিবর্তন করতে পারে।
- `out` — আগে initialize লাগে না, কিন্তু method এর ভেতরে অবশ্যই মান দিতে হবে। (যেমন `int.TryParse(s, out int n)`)
- `in` — reference হিসেবে যায় কিন্তু read-only, বড় struct এ copy এড়াতে।

### Q30. 🟢 `==` আর `.Equals()` এর পার্থক্য?
**উত্তর:** Reference type এ `==` default ভাবে reference (একই object কিনা) তুলনা করে, `.Equals()` override করে value তুলনা করা যায়। `string` এ দুটোই value তুলনা করে কারণ string এ `==` overload করা আছে। Value type এ দুটোই value তুলনা করে।

### Q31. 🟢 `var`, `dynamic` ও `object` এর পার্থক্য?
**উত্তর:**
- `var` — compile-time এ type ঠিক হয়ে যায় (strongly typed), শুধু লেখা সংক্ষিপ্ত।
- `dynamic` — type check run-time এ হয়; ভুল হলে run-time error।
- `object` — সব type এর base; ব্যবহার করতে cast লাগে।

### Q32. 🟢 Nullable type কী? `??` ও `?.` operator কী করে?
**উত্তর:** `int?` মানে `Nullable<int>` — value type কে null রাখার সুযোগ দেয় (যেমন database এর nullable column)।
```csharp
int? discount = null;
int final = discount ?? 0;            // null হলে 0
string? city = customer?.Address?.City; // কোথাও null হলে পুরোটা null, exception নয়
```
C# 8+ এ **Nullable Reference Types** (`string?`) চালু করলে compiler null warning দেয়।

### Q33. 🟢 Array, ArrayList, List<T> এর পার্থক্য?
**উত্তর:** Array — fixed size, typed। ArrayList — dynamic size কিন্তু `object` রাখে (boxing, type-safe নয়, এখন obsolete-প্রায়)। `List<T>` — dynamic size, generic, type-safe — সবচেয়ে বেশি ব্যবহৃত।

### Q34. 🟢 `Dictionary<TKey,TValue>` কখন ব্যবহার করবেন?
**উত্তর:** যখন key দিয়ে দ্রুত (O(1) গড়ে) খুঁজতে হবে। যেমন ProductId দিয়ে Product খোঁজা। List এ `Find` করলে O(n)।
```csharp
var map = products.ToDictionary(p => p.Id);
if (map.TryGetValue(id, out var product)) { ... }
```

### Q35. 🟢 `IEnumerable`, `ICollection`, `IList`, `IQueryable` এর পার্থক্য?
**উত্তর:**
- `IEnumerable<T>` — শুধু foreach দিয়ে পড়া যায়, in-memory।
- `ICollection<T>` — এর সাথে `Count`, `Add`, `Remove`।
- `IList<T>` — এর সাথে index দিয়ে access (`list[0]`)।
- `IQueryable<T>` — query expression tree হিসেবে থাকে, database এ গিয়ে SQL হয়ে execute হয়। EF Core এ `Where` টা `IQueryable` এর উপর করলে filter SQL এ যায়; `IEnumerable` এ নিয়ে এলে পুরো table memory তে চলে আসে।

### Q36. 🟡 `IEnumerable` vs `IQueryable` — একটা practical ভুল দেখান।
**উত্তর:**
```csharp
// ভুল: ToList() আগে করায় সব row memory তে আসবে
var list = db.Invoices.ToList().Where(i => i.Total > 1000);

// সঠিক: filter SQL এ যাবে → WHERE Total > 1000
var list = db.Invoices.Where(i => i.Total > 1000).ToList();
```
লাখ row এর table এ প্রথমটা server এর memory শেষ করে দিতে পারে।

### Q37. 🟢 LINQ কী? কয়েকটা common method বলুন।
**উত্তর:** Language Integrated Query — C# এর ভেতরেই collection/database query লেখার পদ্ধতি। Common: `Where`, `Select`, `OrderBy`, `GroupBy`, `Join`, `First/FirstOrDefault`, `Single`, `Any`, `All`, `Count`, `Sum`, `Skip/Take`, `Distinct`।
```csharp
var top = orders.Where(o => o.Status == "Paid")
                .GroupBy(o => o.CustomerId)
                .Select(g => new { Customer = g.Key, Total = g.Sum(x => x.Amount) })
                .OrderByDescending(x => x.Total).Take(5);
```

### Q38. 🟢 `First`, `FirstOrDefault`, `Single`, `SingleOrDefault` এর পার্থক্য?
**উত্তর:** `First` — প্রথমটা দেয়, না পেলে exception। `FirstOrDefault` — না পেলে default/null। `Single` — ঠিক একটা থাকতে হবে, শূন্য বা একাধিক হলে exception। `SingleOrDefault` — শূন্য হলে null, একাধিক হলে exception। Unique key (যেমন Email) এর জন্য `SingleOrDefault` data bug ধরতে সাহায্য করে।

### Q39. 🟡 Deferred execution কী?
**উত্তর:** LINQ query লেখার সময় execute হয় না, যখন enumerate করা হয় (`foreach`, `ToList()`, `Count()`) তখন হয়। ফলে একই query দুবার enumerate করলে দুবার database এ যায়। একবার `ToList()` করে রেখে দিলে সমস্যা থাকে না।

### Q40. 🟢 Exception handling কীভাবে করেন? `finally` কখন চলে?
**উত্তর:**
```csharp
try { SaveInvoice(); }
catch (DbUpdateException ex) { _logger.LogError(ex, "DB error"); throw; }
catch (Exception ex) { _logger.LogError(ex, "Unknown"); throw; }
finally { /* সবসময় চলে — connection/file বন্ধ করা */ }
```
নির্দিষ্ট exception আগে, general পরে। Exception গিলে ফেলবেন না (`catch {}` খালি রাখবেন না)।

### Q41. 🟡 `throw` আর `throw ex` এর পার্থক্য?
**উত্তর:** `throw;` original stack trace রেখে দেয়। `throw ex;` stack trace reset করে — ফলে আসল error কোথায় হয়েছিল হারিয়ে যায়। সবসময় `throw;` ব্যবহার করুন।

### Q42. 🟢 `using` statement কী কাজে লাগে?
**উত্তর:** `IDisposable` object (DB connection, file stream) কাজ শেষে নিশ্চিতভাবে `Dispose()` করে, exception হলেও।
```csharp
using var conn = new SqlConnection(cs);
conn.Open();
// method শেষে আপনাআপনি Dispose
```

### Q43. 🟡 Garbage Collector কীভাবে কাজ করে? Generation কী?
**উত্তর:** GC heap এ এমন object খুঁজে মুছে দেয় যাদের আর কোনো reference নেই। Heap তিন generation এ ভাগ: **Gen 0** (নতুন, ঘন ঘন collect), **Gen 1** (মাঝারি), **Gen 2** (দীর্ঘজীবী, কম collect)। বড় object (৮৫KB+) **LOH** এ যায়। Unmanaged resource (file, connection) GC নিজে ছাড়ে না — তাই `Dispose` লাগে।

### Q44. 🟡 `IDisposable` আর Finalizer এর পার্থক্য?
**উত্তর:** `Dispose()` আমরা নিজে (বা `using`) ডাকি — deterministic। Finalizer (`~ClassName`) GC তার ইচ্ছামতো সময়ে ডাকে — non-deterministic, এবং performance খরচ বাড়ায়। সাধারণ app এ শুধু `IDisposable` + `using` যথেষ্ট।

### Q45. 🟢 Delegate কী? `Func`, `Action`, `Predicate` কী?
**উত্তর:** Delegate হল method এর type-safe reference/pointer।
- `Action<T>` — return করে না (`void`)।
- `Func<T, TResult>` — শেষ type parameter টা return type।
- `Predicate<T>` — `bool` return করে।
```csharp
Func<int, int, int> add = (a, b) => a + b;
Action<string> log = msg => Console.WriteLine(msg);
Predicate<int> isEven = n => n % 2 == 0;
```

### Q46. 🟡 Event কী? Delegate থেকে কীভাবে আলাদা?
**উত্তর:** Event হল delegate এর উপর একটা নিরাপদ wrapper — বাইরের class শুধু `+=`/`-=` করতে পারে, নিজে invoke করতে বা reset করতে পারে না। Publisher-subscriber pattern এ ব্যবহার হয় (যেমন `InvoicePaid` event হলে SMS পাঠানো)।

### Q47. 🟢 Lambda expression কী?
**উত্তর:** Anonymous function লেখার সংক্ষিপ্ত রূপ: `(parameters) => expression`। LINQ এ সবচেয়ে বেশি ব্যবহৃত: `x => x.Price > 100`।

### Q48. 🟢 Generic কী? কেন ব্যবহার করব?
**উত্তর:** Type কে parameter হিসেবে নিয়ে reusable ও type-safe code লেখা। যেমন একটাই `Repository<T>` দিয়ে Customer, Product সব entity সামলানো যায়, boxing ও casting লাগে না।
```csharp
public class Repository<T> where T : class, IEntity { ... }
```
`where` দিয়ে **constraint** দেওয়া যায়।

### Q49. 🟢 Extension method কী?
**উত্তর:** কোনো class পরিবর্তন না করে তাতে নতুন method যোগ করার উপায়। static class এর static method, প্রথম parameter এ `this`।
```csharp
public static class StringExt {
    public static string ToBdPhone(this string s) => s.StartsWith("0") ? "+88" + s : s;
}
"01711000000".ToBdPhone(); // +8801711000000
```
LINQ এর সব method আসলে extension method।

### Q50. 🟡 `async`/`await` কীভাবে কাজ করে?
**উত্তর:** I/O কাজ (DB, HTTP, file) এর সময় thread কে block না করে ছেড়ে দেয়, কাজ শেষ হলে বাকি code চলে। Web app এ এতে একই সংখ্যক thread দিয়ে বেশি request সামলানো যায় (scalability)।
```csharp
public async Task<Invoice?> GetAsync(int id)
    => await _db.Invoices.FirstOrDefaultAsync(x => x.Id == id);
```
`async` মানেই নতুন thread নয়।

### Q51. 🟡 `.Result` বা `.Wait()` কেন ব্যবহার করা উচিত নয়?
**উত্তর:** এগুলো async কাজকে sync ভাবে block করে — thread নষ্ট হয়, এবং পুরনো ASP.NET/UI app এ **deadlock** হতে পারে। নিয়ম: "async all the way" — controller থেকে repository পর্যন্ত সব `async`/`await`।

### Q52. 🟡 `Task` আর `Thread` এর পার্থক্য? `Task.WhenAll` কখন?
**উত্তর:** `Thread` হল OS level এর থ্রেড, ভারী। `Task` হল একটা কাজের প্রতিনিধিত্ব, thread pool ব্যবহার করে, হালকা ও async-বান্ধব। কয়েকটা স্বাধীন I/O কাজ একসাথে চালাতে:
```csharp
var t1 = _api.GetStockAsync(); var t2 = _api.GetPriceAsync();
await Task.WhenAll(t1, t2);
```

### Q53. 🟡 `async void` কেন বিপজ্জনক?
**উত্তর:** `async void` method এর exception caller ধরতে পারে না, app crash করতে পারে, এবং await করা যায় না। শুধু event handler এ চলে; বাকি সব জায়গায় `async Task`।

### Q54. 🟢 `struct` আর `class` এর পার্থক্য?
**উত্তর:** `struct` value type, inheritance নেই (interface implement করতে পারে), ছোট ও immutable data এর জন্য (যেমন `Point`, `Money`)। `class` reference type, inheritance আছে, বড় ও পরিবর্তনশীল object এর জন্য।

### Q55. 🟡 `record` type কী?
**উত্তর:** C# 9 এর record মূলত data রাখার জন্য — value-based equality (একই data হলে `==` true), built-in `ToString`, এবং `with` দিয়ে copy। DTO এর জন্য চমৎকার।
```csharp
public record ProductDto(int Id, string Name, decimal Price);
var p2 = p1 with { Price = 500 };
```

### Q56. 🟢 টাকার হিসাবে `double` না `decimal`?
**উত্তর:** সবসময় **`decimal`**। `double` binary floating point, তাই `0.1 + 0.2 != 0.3` এর মতো rounding error হয়। Invoice, VAT, salary এ ১ পয়সার ভুলও accounting mismatch করে। SQL Server এ `decimal(18,2)`।

### Q57. 🟡 `static` class/member কখন ব্যবহার করবেন? সমস্যা কী?
**উত্তর:** State ছাড়া utility method (যেমন `Math`, helper extension) এর জন্য। সমস্যা: static mutable state web app এ সব request শেয়ার করে — thread-safety bug হয়, এবং unit test/mock করা কঠিন। Business logic এ static এর বদলে DI দিয়ে service inject করুন।

## ৩. OOP ও Design Principles

### Q58. 🟢 OOP এর ৪টি মূল স্তম্ভ কী?
**উত্তর:**
1. **Encapsulation** — data ও তার উপর কাজ করা method একসাথে রাখা, বাইরে থেকে সরাসরি data পরিবর্তন আটকানো (`private` field + public method/property)।
2. **Abstraction** — জটিলতা লুকিয়ে শুধু দরকারি জিনিস দেখানো (interface/abstract class)।
3. **Inheritance** — একটা class অন্য class এর গুণ পায় (`class Doctor : Employee`)।
4. **Polymorphism** — একই method নাম, ভিন্ন আচরণ (overloading/overriding)।

### Q59. 🟢 Encapsulation এর একটা বাস্তব উদাহরণ দিন।
**উত্তর:**
```csharp
public class BankAccount {
    public decimal Balance { get; private set; }
    public void Withdraw(decimal amount) {
        if (amount > Balance) throw new InvalidOperationException("Insufficient balance");
        Balance -= amount;
    }
}
```
বাইরে থেকে `Balance = -500` করা যায় না, শুধু নিয়ম মেনে `Withdraw` করা যায়।

### Q60. 🟢 Abstract class আর Interface এর পার্থক্য?
**উত্তর:**
| Abstract class | Interface |
|---|---|
| একটাই inherit করা যায় | একাধিক implement করা যায় |
| constructor, field, implemented method রাখা যায় | contract; C# 8+ এ default method রাখা যায়, field নয় |
| "is-a" সম্পর্ক (Doctor is an Employee) | "can-do" ক্ষমতা (IPrintable, IExportable) |

সাধারণ নিয়ম: common code share করতে abstract class, contract/DI এর জন্য interface।

### Q61. 🟢 Method Overloading আর Overriding এর পার্থক্য?
**উত্তর:** **Overloading** — একই class এ একই নাম, ভিন্ন parameter; compile-time polymorphism। **Overriding** — child class এ parent এর `virtual` method নতুনভাবে লেখা (`override`); run-time polymorphism।
```csharp
public virtual decimal CalculateSalary() => Basic;          // Employee
public override decimal CalculateSalary() => Basic + OnCallAllowance; // Doctor
```

### Q62. 🟡 `override` আর `new` (method hiding) এর পার্থক্য?
**উত্তর:** `override` এ parent reference দিয়ে ডাকলেও child এর method চলে। `new` এ parent reference দিয়ে ডাকলে parent এর method চলে — এটা প্রায়ই bug এর উৎস।
```csharp
Employee e = new Doctor();
e.CalculateSalary(); // override → Doctor এর; new → Employee এর
```

### Q63. 🟢 Access modifier গুলো কী কী?
**উত্তর:** `public` (সবখানে), `private` (শুধু একই class), `protected` (class ও child class), `internal` (একই assembly/project), `protected internal` (একই assembly অথবা child), `private protected` (একই assembly এর child)। Class এর default `internal`, member এর default `private`।

### Q64. 🟢 `sealed` class কী?
**উত্তর:** যাকে আর inherit করা যায় না। Security বা design এর কারণে (যেমন `string` sealed)। Sealed class এ JIT কিছুটা optimization ও করতে পারে।

### Q65. 🟢 Constructor এর ধরন? Static constructor কখন চলে?
**উত্তর:** Default, Parameterized, Copy, Private (Singleton এ), Static। Static constructor class প্রথমবার ব্যবহারের আগে ঠিক একবার চলে, parameter নেয় না — static data initialize করতে।

### Q66. 🟢 SOLID principle গুলো ব্যাখ্যা করুন।
**উত্তর:**
- **S — Single Responsibility:** একটা class এর একটাই দায়িত্ব। `InvoiceService` হিসাব করবে, PDF বানাবে `InvoicePdfGenerator`।
- **O — Open/Closed:** নতুন feature এর জন্য extend করো, পুরনো code modify নয়। নতুন payment method (bKash, Nagad) → নতুন class যা `IPaymentGateway` implement করে।
- **L — Liskov Substitution:** child class কে parent এর জায়গায় বসালে program ভাঙবে না।
- **I — Interface Segregation:** বড় interface ভেঙে ছোট ছোট interface; কেউ যেন অপ্রয়োজনীয় method implement করতে বাধ্য না হয়।
- **D — Dependency Inversion:** high-level class concrete class এর উপর নয়, abstraction (interface) এর উপর নির্ভর করবে → DI।

### Q67. 🟡 Open/Closed principle এর বাংলাদেশি উদাহরণ code এ দেখান।
**উত্তর:**
```csharp
public interface IPaymentGateway { Task<bool> PayAsync(decimal amount); }
public class BkashGateway : IPaymentGateway { ... }
public class NagadGateway : IPaymentGateway { ... }
public class SslCommerzGateway : IPaymentGateway { ... }
```
নতুন gateway (যেমন Rocket) এলে শুধু নতুন class, `CheckoutService` এর `if-else` বাড়াতে হয় না।

### Q68. 🟡 Composition আর Inheritance — কোনটা ভালো?
**উত্তর:** "Favor composition over inheritance"। Inheritance শক্ত coupling তৈরি করে, গভীর hierarchy ভাঙা কঠিন। Composition এ class অন্য object কে field হিসেবে রাখে (has-a), সহজে বদলানো ও test করা যায়। যেমন `OrderService` এর ভেতরে `IPaymentGateway` ও `INotificationService` inject করা।

### Q69. 🟢 Design pattern কী? কয়েকটার নাম বলুন যা আপনি ব্যবহার করেছেন।
**উত্তর:** বারবার আসা সমস্যার পরীক্ষিত সমাধান। .NET এ common: **Repository**, **Unit of Work**, **Dependency Injection**, **Singleton**, **Factory**, **Strategy**, **Observer** (event), **Decorator** (middleware), **Builder** (`WebApplication.CreateBuilder`), **Adapter**।

### Q70. 🟢 Singleton pattern কী? Thread-safe Singleton লিখুন।
**উত্তর:** একটা class এর পুরো app এ শুধু একটা instance থাকবে।
```csharp
public sealed class AppConfig {
    private static readonly Lazy<AppConfig> _instance = new(() => new AppConfig());
    public static AppConfig Instance => _instance.Value;
    private AppConfig() { }
}
```
ASP.NET Core এ নিজে লেখার বদলে `services.AddSingleton<T>()` ব্যবহার করাই ভালো।

### Q71. 🟡 Repository ও Unit of Work pattern কী?
**উত্তর:** **Repository** — data access logic (CRUD) business logic থেকে আলাদা করে, যেন service জানে না data SQL থেকে আসছে নাকি API থেকে। **Unit of Work** — একাধিক repository এর পরিবর্তন একটা transaction এ একসাথে save করে (`_uow.SaveChangesAsync()`)। লক্ষ্য রাখুন: EF Core এর `DbContext` নিজেই একটা Unit of Work এবং `DbSet` একটা Repository — তাই অনেকে আলাদা layer না বানিয়ে সরাসরি DbContext ব্যবহার করেন। দুটো মতই interview এ বলতে পারেন।

### Q72. 🟡 Factory ও Strategy pattern এর পার্থক্য?
**উত্তর:** **Factory** — কোন object বানাতে হবে সেই সিদ্ধান্ত এক জায়গায় রাখে (`ReportFactory.Create("pdf")`)। **Strategy** — একই কাজের বিভিন্ন algorithm interchangeable রাখে (ডিসকাউন্ট হিসাব: `RegularDiscount`, `CorporateDiscount`)। প্রায়ই Factory দিয়ে সঠিক Strategy বেছে নেওয়া হয়।

### Q73. 🟢 DRY, KISS, YAGNI কী?
**উত্তর:** **DRY** — Don't Repeat Yourself, একই logic একাধিক জায়গায় লিখবেন না। **KISS** — Keep It Simple, Stupid। **YAGNI** — You Aren't Gonna Need It, ভবিষ্যতে লাগতে পারে ভেবে এখনই অপ্রয়োজনীয় feature বানাবেন না।

### Q74. 🟡 Clean / Layered / N-Tier architecture কী? আপনার project এর layer গুলো কী ছিল?
**উত্তর:** Code কে দায়িত্ব অনুযায়ী layer এ ভাগ করা:
- **Presentation** (Angular / MVC View / API Controller)
- **Application/Service** (business logic, DTO, validation)
- **Domain** (Entity, business rule)
- **Infrastructure/Data** (EF Core, repository, external API)

Clean Architecture এ dependency সবসময় ভেতরের দিকে — Domain কারো উপর নির্ভর করে না।

### Q75. 🟡 Coupling ও Cohesion কী?
**উত্তর:** **Coupling** — class গুলো একে অপরের উপর কতটা নির্ভরশীল; **কম** হওয়া ভালো (loose coupling)। **Cohesion** — একটা class এর ভেতরের জিনিসগুলো কতটা একই উদ্দেশ্যে; **বেশি** হওয়া ভালো (high cohesion)। Interface + DI দিয়ে loose coupling আসে।

## ৪. ASP.NET Core

### Q76. 🟢 ASP.NET Core কী? পুরনো ASP.NET থেকে সুবিধা কী?
**উত্তর:** Microsoft এর cross-platform, open-source, high-performance web framework। সুবিধা: Linux/Docker এ চলে, built-in Dependency Injection, middleware pipeline, Kestrel server (অনেক দ্রুত), MVC ও Web API একই framework এ, `appsettings.json` ভিত্তিক configuration, modular (যা দরকার শুধু সেটুকু package)।

### Q77. 🟢 `Program.cs` এ কী থাকে? `Startup.cs` কোথায় গেল?
**উত্তর:** .NET 6 থেকে Minimal hosting model — `Startup.cs` এর `ConfigureServices` ও `Configure` এখন `Program.cs` এই।
```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();                      // DI registration
builder.Services.AddDbContext<AppDbContext>(o => o.UseSqlServer(
    builder.Configuration.GetConnectionString("Default")));
var app = builder.Build();
app.UseHttpsRedirection();                               // middleware pipeline
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
app.Run();
```

### Q78. 🟢 Middleware কী?
**উত্তর:** Request ও Response pipeline এর মধ্যে থাকা component। প্রতিটা middleware request কে কিছু করে পরেরটায় পাঠায় (`next()`), বা নিজেই response দিয়ে থামিয়ে দিতে পারে (short-circuit)। উদাহরণ: exception handling, HTTPS redirect, static files, routing, CORS, authentication, authorization।

### Q79. 🟡 Middleware এর ক্রম কেন গুরুত্বপূর্ণ? সঠিক ক্রম কী?
**উত্তর:** Request উপর থেকে নিচে, response নিচ থেকে উপরে যায়। ভুল ক্রমে যেমন `UseAuthorization` কে `UseAuthentication` এর আগে দিলে user কে চেনার আগেই permission check হবে — সব request 401। সাধারণ ক্রম:
`ExceptionHandler → HSTS → HttpsRedirection → StaticFiles → Routing → CORS → Authentication → Authorization → Endpoints`

### Q80. 🟡 Custom middleware লিখুন — প্রতিটা request এর সময় log করবে।
**উত্তর:**
```csharp
public class TimingMiddleware {
    private readonly RequestDelegate _next;
    private readonly ILogger<TimingMiddleware> _log;
    public TimingMiddleware(RequestDelegate next, ILogger<TimingMiddleware> log)
        { _next = next; _log = log; }
    public async Task InvokeAsync(HttpContext ctx) {
        var sw = Stopwatch.StartNew();
        await _next(ctx);
        _log.LogInformation("{Path} took {Ms} ms", ctx.Request.Path, sw.ElapsedMilliseconds);
    }
}
// Program.cs
app.UseMiddleware<TimingMiddleware>();
```

### Q81. 🟡 `app.Use`, `app.Run`, `app.Map` এর পার্থক্য?
**উত্তর:** `Use` — কাজ করে পরের middleware এ পাঠাতে পারে। `Run` — terminal, পরের middleware ডাকে না। `Map` — নির্দিষ্ট path এর জন্য আলাদা branch তৈরি করে।

### Q82. 🟢 Dependency Injection (DI) কী? কেন দরকার?
**উত্তর:** Class নিজে dependency `new` করে বানায় না, বাইরে থেকে (সাধারণত constructor দিয়ে) পায়। সুবিধা: loose coupling, unit test এ mock দেওয়া যায়, implementation বদলানো সহজ।
```csharp
builder.Services.AddScoped<IInvoiceService, InvoiceService>();
public class InvoiceController(IInvoiceService svc) : ControllerBase { ... }
```

### Q83. 🟢 Service lifetime — Transient, Scoped, Singleton এর পার্থক্য?
**উত্তর:**
- **Transient** — যতবার চাওয়া হবে ততবার নতুন instance। হালকা, stateless service।
- **Scoped** — প্রতি HTTP request এ একটা instance। `DbContext` সবসময় Scoped।
- **Singleton** — পুরো application এ একটাই instance। Cache, configuration।

### Q84. 🔴 Singleton এর ভেতরে Scoped service inject করলে কী হয়?
**উত্তর:** একে **captive dependency** বলে। Singleton চিরকাল থাকে, তাই তার ভেতরের `DbContext` ও চিরকাল একটাই থেকে যায় — সব request একই DbContext শেয়ার করে → thread-safety error, stale data, memory leak। Development এ ASP.NET Core exception দেয় ("Cannot consume scoped service from singleton")। সমাধান: Singleton এ `IServiceScopeFactory` inject করে প্রয়োজনমতো scope তৈরি করা।
```csharp
using var scope = _scopeFactory.CreateScope();
var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
```

### Q85. 🟢 `appsettings.json` ও Configuration কীভাবে কাজ করে?
**উত্তর:** Configuration একাধিক উৎস থেকে layer হিসেবে পড়ে, পরেরটা আগেরটাকে override করে: `appsettings.json` → `appsettings.{Environment}.json` → User Secrets (Development) → Environment variables → Command-line args।
```csharp
var cs = builder.Configuration.GetConnectionString("Default");
var smsKey = builder.Configuration["Sms:ApiKey"];
```

### Q86. 🟡 Options pattern (`IOptions<T>`) কী?
**উত্তর:** Configuration section কে strongly-typed class এ bind করা।
```csharp
public class SmsSettings { public string ApiKey { get; set; } = ""; public string SenderId { get; set; } = ""; }
builder.Services.Configure<SmsSettings>(builder.Configuration.GetSection("Sms"));
public class SmsService(IOptions<SmsSettings> opt) { var key = opt.Value.ApiKey; }
```
`IOptionsSnapshot` প্রতি request এ নতুন মান পড়ে, `IOptionsMonitor` change হলে live update দেয়।

### Q87. 🟡 Password/API key কোথায় রাখবেন? `appsettings.json` এ commit করবেন?
**উত্তর:** না। Development এ **User Secrets** (`dotnet user-secrets set`), Production এ **Environment variable** বা **Azure Key Vault**/secret manager। Secret কখনো Git এ commit নয় — একবার push হলে history তে থেকে যায়, key rotate করতে হয়।

### Q88. 🟢 Environment (Development/Staging/Production) কীভাবে set করবেন?
**উত্তর:** `ASPNETCORE_ENVIRONMENT` environment variable দিয়ে। Code এ `app.Environment.IsDevelopment()` দিয়ে check করা যায় — যেমন Development এ শুধু Swagger ও detailed error page দেখানো।

### Q89. 🟢 Routing কী? Conventional vs Attribute routing?
**উত্তর:** URL কে কোন controller/action handle করবে তা ঠিক করা।
- **Conventional:** `app.MapControllerRoute("default", "{controller=Home}/{action=Index}/{id?}")` — MVC তে common।
- **Attribute:** Controller/action এর উপর লেখা — Web API তে standard।
```csharp
[Route("api/[controller]")]
public class InvoicesController : ControllerBase {
    [HttpGet("{id:int}")] public IActionResult Get(int id) => ...;
}
```

### Q90. 🟢 Route constraint কী?
**উত্তর:** Route parameter এর type/format নির্দিষ্ট করা: `{id:int}`, `{code:alpha}`, `{date:datetime}`, `{id:guid}`, `{page:min(1)}`। না মিললে সেই route match করবে না (404)।

### Q91. 🟢 Model Binding কী? `[FromBody]`, `[FromQuery]`, `[FromRoute]`, `[FromForm]`?
**উত্তর:** HTTP request এর data কে action এর parameter/object এ বসানো।
- `[FromRoute]` — URL path থেকে (`/invoices/5`)
- `[FromQuery]` — query string থেকে (`?page=2`)
- `[FromBody]` — JSON body থেকে (POST/PUT)
- `[FromForm]` — form data / file upload
- `[FromHeader]` — header থেকে

`[ApiController]` attribute থাকলে complex type ধরে নেয় `[FromBody]`।

### Q92. 🟢 Model Validation কীভাবে করেন?
**উত্তর:** Data Annotation দিয়ে:
```csharp
public class CreateCustomerDto {
    [Required, StringLength(100)] public string Name { get; set; } = "";
    [Required, RegularExpression(@"^01[3-9]\d{8}$", ErrorMessage = "সঠিক মোবাইল নম্বর দিন")]
    public string Mobile { get; set; } = "";
    [EmailAddress] public string? Email { get; set; }
    [Range(0, 1000000)] public decimal CreditLimit { get; set; }
}
```
`[ApiController]` থাকলে invalid হলে নিজে থেকেই 400 Bad Request ফেরত দেয়। জটিল নিয়মের জন্য **FluentValidation** library জনপ্রিয়।

### Q93. 🟡 `[ApiController]` attribute কী কী সুবিধা দেয়?
**উত্তর:** (১) Automatic 400 response যখন ModelState invalid, (২) Attribute routing বাধ্যতামূলক, (৩) Binding source inference (complex type → body), (৪) Error response `ProblemDetails` format এ।

### Q94. 🟢 `IActionResult` ও `ActionResult<T>` এর পার্থক্য?
**উত্তর:** `IActionResult` যেকোনো result দিতে পারে কিন্তু return type জানা যায় না। `ActionResult<T>` এ data type জানা থাকে (Swagger এ schema দেখায়) এবং সরাসরি `T` return করা যায়।
```csharp
public async Task<ActionResult<InvoiceDto>> Get(int id) {
    var inv = await _svc.GetAsync(id);
    if (inv is null) return NotFound();
    return inv;
}
```

### Q95. 🟢 Filter কী? কয়টা ধরন আছে?
**উত্তর:** Action এর আগে/পরে নির্দিষ্ট code চালানো (MVC pipeline এর ভেতরে)। ক্রম অনুযায়ী: **Authorization** → **Resource** → **Action** → **Exception** → **Result** filter। Logging, validation, caching, audit trail এর জন্য ব্যবহার হয়।

### Q96. 🟡 Middleware আর Filter এর পার্থক্য?
**উত্তর:** Middleware পুরো app এর সব request এ চলে (static file সহ), HttpContext নিয়ে কাজ করে। Filter শুধু MVC/API action এর আশেপাশে চলে এবং action এর context জানে (কোন controller, কোন argument, ModelState)। Action-specific কাজ (যেমন একটা নির্দিষ্ট action এ audit log) → Filter; global কাজ (exception, CORS) → Middleware।

### Q97. 🟡 Global exception handling কীভাবে করেন?
**উত্তর:** প্রতিটা action এ try-catch না লিখে এক জায়গায়:
```csharp
app.UseExceptionHandler(err => err.Run(async ctx => {
    var ex = ctx.Features.Get<IExceptionHandlerFeature>()?.Error;
    ctx.Response.StatusCode = 500;
    await ctx.Response.WriteAsJsonAsync(new { message = "Something went wrong" });
}));
```
.NET 8 এ `IExceptionHandler` interface implement করেও করা যায়। Production এ client কে stack trace দেখাবেন না, শুধু log এ রাখবেন।

### Q98. 🟢 Authentication আর Authorization এর পার্থক্য?
**উত্তর:** **Authentication** — "তুমি কে?" (login, identity যাচাই)। **Authorization** — "তুমি কী করতে পারবে?" (permission)। Authentication আগে, তারপর Authorization। ব্যর্থ হলে Authentication → **401 Unauthorized**, Authorization → **403 Forbidden**।

### Q99. 🟢 JWT কী? এর গঠন কেমন?
**উত্তর:** JSON Web Token — stateless authentication token। তিন অংশ, ডট দিয়ে আলাদা: `Header.Payload.Signature`।
- **Header:** algorithm (HS256)
- **Payload:** claims (userId, role, exp)
- **Signature:** secret key দিয়ে sign — কেউ payload বদলালে signature মিলবে না।

Payload শুধু Base64 encoded, **encrypted নয়** — তাই password বা sensitive data JWT তে রাখবেন না।

### Q100. 🟡 ASP.NET Core এ JWT authentication setup করুন।
**উত্তর:**
```csharp
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
  .AddJwtBearer(o => o.TokenValidationParameters = new() {
      ValidateIssuer = true, ValidateAudience = true,
      ValidateLifetime = true, ValidateIssuerSigningKey = true,
      ValidIssuer = cfg["Jwt:Issuer"], ValidAudience = cfg["Jwt:Audience"],
      IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(cfg["Jwt:Key"]!))
  });
// controller
[Authorize(Roles = "Admin,Accountant")]
public class ReportsController : ControllerBase { }
```
Angular client প্রতিটা request এ header পাঠায়: `Authorization: Bearer <token>`।

### Q101. 🟡 Access token ও Refresh token কেন আলাদা?
**উত্তর:** Access token এর মেয়াদ কম (১৫-৬০ মিনিট) রাখা হয় যাতে চুরি হলেও ক্ষতি সীমিত। Refresh token এর মেয়াদ বেশি (দিন), server এ DB তে রাখা হয়, এবং দিয়ে নতুন access token নেওয়া যায় — user কে বারবার login করতে হয় না। Logout এ refresh token revoke করা যায়।

### Q102. 🟡 Role-based আর Policy-based authorization এর পার্থক্য?
**উত্তর:** Role-based: `[Authorize(Roles = "Admin")]` — সরল। Policy-based: জটিল নিয়ম, claim/requirement দিয়ে।
```csharp
builder.Services.AddAuthorization(o =>
    o.AddPolicy("CanApproveInvoice", p => p.RequireClaim("permission", "invoice.approve")));
[Authorize(Policy = "CanApproveInvoice")]
```
B2B ERP তে সাধারণত permission-based (প্রতিটা feature এর আলাদা permission) ব্যবহার হয়, যা policy দিয়ে implement করা হয়।

### Q103. 🟢 Cookie authentication আর JWT এর পার্থক্য? কখন কোনটা?
**উত্তর:** Cookie — server-rendered MVC app এ সুবিধাজনক, browser নিজে পাঠায়, CSRF protection লাগে। JWT — SPA (Angular), mobile app ও API এর জন্য, stateless, একাধিক server এ সহজে scale হয়। Angular + Web API → সাধারণত JWT।

### Q104. 🟢 CORS কী? কখন error দেয়?
**উত্তর:** Cross-Origin Resource Sharing — browser এর security নিয়ম। Angular `http://localhost:4200` থেকে API `https://localhost:5001` কে call করলে origin আলাদা, তাই API অনুমতি না দিলে browser response block করে।
```csharp
builder.Services.AddCors(o => o.AddPolicy("ng", p =>
    p.WithOrigins("http://localhost:4200").AllowAnyHeader().AllowAnyMethod()));
app.UseCors("ng");
```
Production এ `AllowAnyOrigin` ব্যবহার করবেন না। Postman এ CORS error হয় না কারণ এটা browser এর নিয়ম।

### Q105. 🟢 Logging কীভাবে করেন?
**উত্তর:** Built-in `ILogger<T>` inject করে। Level: Trace, Debug, Information, Warning, Error, Critical। Production এ file/DB/Seq এ লেখার জন্য **Serilog** বা **NLog** জনপ্রিয়। Structured logging ব্যবহার করুন:
```csharp
_logger.LogInformation("Invoice {InvoiceNo} created for {CustomerId}", no, custId);
```
String interpolation (`$"..."`) এর বদলে template ব্যবহার করলে log search করা সহজ।

### Q106. 🟡 Caching — In-Memory vs Distributed? কখন কোনটা?
**উত্তর:** `IMemoryCache` — একই server এর memory তে, দ্রুত, কিন্তু server restart এ হারায় এবং একাধিক server এ sync থাকে না। `IDistributedCache` (Redis/SQL Server) — একাধিক server শেয়ার করে। প্রায় অপরিবর্তনশীল data (district list, product category, settings) cache করুন।
```csharp
var cats = await _cache.GetOrCreateAsync("categories", e => {
    e.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(30);
    return _db.Categories.ToListAsync();
});
```
.NET 9 এ নতুন `HybridCache` ও আছে।

### Q107. 🟡 Background job কীভাবে চালাবেন? (যেমন রাতে report email)
**উত্তর:** ছোট কাজের জন্য `BackgroundService` (`IHostedService`) — app এর সাথে চলে। নির্দিষ্ট সময়ে/retry/dashboard দরকার হলে **Hangfire** বা **Quartz.NET**।
```csharp
public class DailyReportJob : BackgroundService {
    protected override async Task ExecuteAsync(CancellationToken ct) {
        while (!ct.IsCancellationRequested) {
            await SendReportAsync();
            await Task.Delay(TimeSpan.FromHours(24), ct);
        }
    }
}
```

### Q108. 🟡 ASP.NET Core app কীভাবে deploy করেছেন?
**উত্তর:** বাংলাদেশের B2B কোম্পানিতে সবচেয়ে common: Windows Server এ **IIS** (ASP.NET Core Hosting Bundle install করে, `dotnet publish -c Release` এর output IIS site এ)। অন্যান্য: Linux + Nginx reverse proxy + systemd, Docker container, Azure App Service। Angular এর `ng build` output (`dist/`) IIS এ আলাদা site বা API এর `wwwroot` এ রাখা যায় — তখন Angular routing এর জন্য URL Rewrite rule লাগে যাতে refresh এ 404 না হয়।

## ৫. ASP.NET MVC

### Q109. 🟢 MVC pattern কী?
**উত্তর:** **Model** (data ও business logic), **View** (UI — Razor `.cshtml`), **Controller** (request নেয়, Model এর সাথে কাজ করে, কোন View দেখাবে ঠিক করে)। এতে concerns আলাদা থাকে, test ও maintain সহজ হয়।

### Q110. 🟢 MVC request এর life cycle কী?
**উত্তর:** Request → Routing → Controller তৈরি (DI সহ) → Authorization filter → Model binding → Validation → Action filter → Action execute → Result filter → View render → Response।

### Q111. 🟢 ViewData, ViewBag, TempData এর পার্থক্য?
**উত্তর:**
- **ViewData** — dictionary (`ViewData["Title"]`), cast লাগে, শুধু current request।
- **ViewBag** — dynamic wrapper (`ViewBag.Title`), একই data, cast লাগে না।
- **TempData** — পরের request পর্যন্ত থাকে (redirect এর পর success message দেখাতে)। পড়ার পর মুছে যায় (`Keep()`/`Peek()` দিয়ে রাখা যায়)।

সবচেয়ে ভালো: strongly-typed **ViewModel**।

### Q112. 🟢 Partial View, Layout ও View Component এর পার্থক্য?
**উত্তর:** **Layout** — সব page এর common কাঠামো (header, menu, footer) — `_Layout.cshtml`। **Partial View** — reusable UI অংশ, parent এর model পায়, নিজস্ব logic নেই। **View Component** — নিজস্ব logic ও data সহ reusable অংশ (যেমন cart summary, notification bell), controller ছাড়া নিজে data load করে।

### Q113. 🟢 Tag Helper কী? HTML Helper থেকে পার্থক্য?
**উত্তর:** Tag Helper HTML এর মতো দেখতে: `<input asp-for="Name" class="form-control" />`। HTML Helper C# method: `@Html.TextBoxFor(m => m.Name)`। Tag Helper পড়তে সহজ, designer-friendly, ASP.NET Core এ recommended।

### Q114. 🟢 PRG (Post-Redirect-Get) pattern কী?
**উত্তর:** Form POST সফল হলে সরাসরি View return না করে `RedirectToAction` দেওয়া। নাহলে user browser refresh দিলে form আবার submit হয়ে duplicate invoice তৈরি হবে।
```csharp
[HttpPost, ValidateAntiForgeryToken]
public async Task<IActionResult> Create(InvoiceVm vm) {
    if (!ModelState.IsValid) return View(vm);
    await _svc.CreateAsync(vm);
    TempData["Success"] = "Invoice saved";
    return RedirectToAction(nameof(Index));
}
```

### Q115. 🟡 CSRF কী? `[ValidateAntiForgeryToken]` কী করে?
**উত্তর:** Cross-Site Request Forgery — user login থাকা অবস্থায় অন্য website তার browser দিয়ে আমাদের site এ request পাঠিয়ে দেয় (cookie আপনাআপনি যায়)। Anti-forgery token form এ hidden field হিসেবে থাকে, POST এ মিলিয়ে দেখা হয় — বাইরের site সেই token জানে না। Cookie auth এ প্রয়োজন; JWT header ভিত্তিক API তে সাধারণত লাগে না।

### Q116. 🟢 ViewModel কেন ব্যবহার করবেন, সরাসরি Entity কেন নয়?
**উত্তর:** (১) View এ যা দরকার শুধু তা পাঠানো, (২) **Over-posting** আক্রমণ রোধ — Entity bind করলে hacker `IsAdmin=true` বা `Price` form এ পাঠিয়ে পরিবর্তন করতে পারে, (৩) একাধিক entity এর data একসাথে (dropdown list সহ), (৪) View এর validation আলাদা রাখা।

### Q117. 🟢 Area কী?
**উত্তর:** বড় MVC app কে module অনুযায়ী ভাগ করা — প্রতিটা Area এর নিজস্ব Controllers/Views/Models। যেমন ERP তে `Areas/HRM`, `Areas/Accounts`, `Areas/Inventory`। Route এ `[Area("HRM")]` দিতে হয়।

### Q118. 🟡 MVC Controller আর API Controller এর পার্থক্য? Razor Pages কী?
**উত্তর:** MVC Controller `Controller` থেকে inherit করে, View (HTML) return করে। API Controller `ControllerBase` থেকে inherit করে, data (JSON) return করে — View support নেই। **Razor Pages** page-centric model — প্রতিটা page এ `.cshtml` + `PageModel` (`OnGet`, `OnPost`), সাধারণ CRUD form এর জন্য সহজ।

## ৬. REST API Design

### Q119. 🟢 REST কী? এর মূল নীতি কী?
**উত্তর:** Representational State Transfer — HTTP এর উপর ভিত্তি করে API design এর architectural style। নীতি: (১) **Client-Server** আলাদা, (২) **Stateless** — প্রতিটা request এ প্রয়োজনীয় সব তথ্য থাকবে, server session মনে রাখবে না, (৩) **Cacheable**, (৪) **Uniform Interface** — resource URL দিয়ে চিহ্নিত, HTTP verb দিয়ে action, (৫) **Layered System**।

### Q120. 🟢 HTTP method গুলো কী কী? কোনটা কী কাজে?
**উত্তর:**
| Method | কাজ | উদাহরণ |
|---|---|---|
| GET | পড়া | `GET /api/products/5` |
| POST | নতুন তৈরি | `POST /api/products` |
| PUT | পুরোটা update/replace | `PUT /api/products/5` |
| PATCH | আংশিক update | `PATCH /api/products/5` |
| DELETE | মোছা | `DELETE /api/products/5` |

### Q121. 🟢 PUT আর PATCH এর পার্থক্য?
**উত্তর:** PUT এ পুরো resource পাঠাতে হয় — যে field পাঠানো হয়নি তা null/default হয়ে যেতে পারে। PATCH এ শুধু পরিবর্তিত field পাঠানো হয় (যেমন শুধু `status`)।

### Q122. 🟢 Idempotent মানে কী? কোন method idempotent?
**উত্তর:** একই request একবার বা দশবার পাঠালে server এর অবস্থা একই থাকে। **GET, PUT, DELETE** idempotent; **POST** নয় (দশবার POST = দশটা invoice)। **Safe** method (data পরিবর্তন করে না): GET, HEAD, OPTIONS।

### Q123. 🟡 Payment API তে duplicate POST কীভাবে আটকাবেন?
**উত্তর:** **Idempotency key** — client প্রতিটা payment এর জন্য একটা unique key (GUID) header এ পাঠায় (`Idempotency-Key`)। Server key টা DB তে রাখে; একই key আবার এলে নতুন payment না করে আগের result ফেরত দেয়। এর সাথে DB এ unique constraint ও frontend এ submit button disable করা। bKash/নেটওয়ার্ক slow হলে user বারবার click করে — এই সমস্যা বাংলাদেশে খুব বাস্তব।

### Q124. 🟢 গুরুত্বপূর্ণ HTTP status code গুলো বলুন।
**উত্তর:**
- **2xx সফল:** 200 OK, 201 Created (POST সফল, `Location` header সহ), 204 No Content (DELETE সফল)
- **3xx redirect:** 301 Moved Permanently, 302 Found, 304 Not Modified
- **4xx client এর ভুল:** 400 Bad Request (validation), 401 Unauthorized (login নেই), 403 Forbidden (permission নেই), 404 Not Found, 405 Method Not Allowed, 409 Conflict (duplicate), 422 Unprocessable Entity, 429 Too Many Requests
- **5xx server এর ভুল:** 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout

### Q125. 🟢 ভালো REST URL design এর নিয়ম কী?
**উত্তর:**
- Noun, verb নয়: `GET /api/invoices` ✅, `GET /api/getInvoices` ❌
- বহুবচন: `/api/customers`
- Hierarchy: `/api/customers/10/invoices`
- Filter/sort/page query string এ: `/api/invoices?status=paid&page=2&pageSize=20&sort=-date`
- ছোট হাতের অক্ষর, hyphen: `/api/purchase-orders`
- Versioning: `/api/v1/...`

### Q126. 🟡 API versioning কেন ও কীভাবে করবেন?
**উত্তর:** B2B তে একাধিক client (mobile app, অন্য কোম্পানির system) পুরনো API ব্যবহার করে; breaking change করলে তাদের system ভেঙে যাবে। উপায়: URL (`/api/v2/orders`) — সবচেয়ে common, Query string (`?api-version=2.0`), Header (`api-version: 2`)। .NET এ `Asp.Versioning.Mvc` package।

### Q127. 🟡 Pagination কীভাবে implement করবেন?
**উত্তর:**
```csharp
[HttpGet]
public async Task<ActionResult<PagedResult<ProductDto>>> Get(int page = 1, int pageSize = 20) {
    pageSize = Math.Min(pageSize, 100);
    var q = _db.Products.AsNoTracking().OrderBy(p => p.Id);
    var total = await q.CountAsync();
    var items = await q.Skip((page - 1) * pageSize).Take(pageSize)
                       .Select(p => new ProductDto(p.Id, p.Name, p.Price)).ToListAsync();
    return new PagedResult<ProductDto>(items, total, page, pageSize);
}
```
Offset pagination সহজ কিন্তু খুব বড় table এ শেষের page ধীর — তখন **keyset/cursor pagination** (`WHERE Id > @lastId`)। `OrderBy` ছাড়া `Skip` ব্যবহার করবেন না — ক্রম নিশ্চিত থাকে না।

### Q128. 🟢 DTO কী? কেন Entity সরাসরি return করবেন না?
**উত্তর:** Data Transfer Object — API তে যা পাঠানো/নেওয়া হবে শুধু সেটুকুর class। Entity return করলে: (১) `PasswordHash` এর মতো গোপন field বেরিয়ে যায়, (২) navigation property তে **circular reference** error ও বিশাল JSON, (৩) DB schema বদলালে API contract ভেঙে যায়। Mapping হাতে বা **AutoMapper**/**Mapster** দিয়ে।

### Q129. 🟢 Swagger / OpenAPI কী?
**উত্তর:** API এর machine-readable documentation (OpenAPI spec) এবং সেখান থেকে interactive UI — browser থেকেই API test করা যায়। .NET এ Swashbuckle বা .NET 9 এর built-in `Microsoft.AspNetCore.OpenApi`। Frontend team (Angular) এর সাথে contract শেয়ার করতে খুব কাজের।

### Q130. 🟡 API এর error response কেমন হওয়া উচিত?
**উত্তর:** একই format এ — RFC 7807 **ProblemDetails**:
```json
{ "type": "...", "title": "Validation failed", "status": 400,
  "errors": { "Mobile": ["সঠিক মোবাইল নম্বর দিন"] }, "traceId": "00-abc..." }
```
Angular এক জায়গায় (interceptor) সব error একইভাবে handle করতে পারে। `traceId` দিয়ে log এ খোঁজা যায়।

### Q131. 🟡 API কে কীভাবে secure করবেন?
**উত্তর:** HTTPS বাধ্যতামূলক, JWT/OAuth authentication, প্রতিটা endpoint এ authorization (এবং **resource ownership** check — user 5 যেন user 6 এর invoice না দেখে), input validation, parameterized query (SQL injection রোধ), rate limiting, CORS সীমিত রাখা, sensitive data log না করা, error এ stack trace না দেখানো, secret config এ।

### Q132. 🟡 Rate limiting কী? .NET এ কীভাবে?
**উত্তর:** নির্দিষ্ট সময়ে একজন client কতগুলো request পাঠাতে পারবে তার সীমা — brute-force login ও abuse রোধ (যেমন OTP API)। .NET 7+ এ built-in:
```csharp
builder.Services.AddRateLimiter(o => o.AddFixedWindowLimiter("otp", l => {
    l.PermitLimit = 3; l.Window = TimeSpan.FromMinutes(1); }));
app.UseRateLimiter();
[EnableRateLimiting("otp")] public IActionResult SendOtp() { ... }
```
সীমা পার হলে 429।

### Q133. 🟢 REST আর SOAP এর পার্থক্য? GraphQL কী?
**উত্তর:** SOAP — XML ভিত্তিক, কঠোর contract (WSDL), ভারী; পুরনো ব্যাংক/সরকারি system এ এখনো আছে। REST — হালকা, JSON, HTTP verb। **GraphQL** — একটাই endpoint, client ঠিক যে field দরকার শুধু সেগুলো চায়; over-fetching কমায়।

### Q134. 🟡 অন্য কোম্পানির API (যেমন SMS gateway) call করবেন কীভাবে? `new HttpClient()` এ সমস্যা কী?
**উত্তর:** প্রতিবার `new HttpClient()` + dispose করলে **socket exhaustion** হয় (connection TIME_WAIT এ আটকে থাকে)। সমাধান `IHttpClientFactory`:
```csharp
builder.Services.AddHttpClient<SmsClient>(c => {
    c.BaseAddress = new Uri("https://api.sms-provider.com/");
    c.Timeout = TimeSpan.FromSeconds(10);
});
```
সাথে **Polly** (বা .NET 8 এর `Microsoft.Extensions.Http.Resilience`) দিয়ে retry ও circuit breaker — বাইরের API মাঝে মাঝে down থাকে।

## ৭. SQL Server ও Entity Framework Core

### Q135. 🟢 Primary Key, Foreign Key, Unique Key এর পার্থক্য?
**উত্তর:** **Primary Key** — প্রতিটা row কে আলাদা চিহ্নিত করে, null হয় না, table এ একটাই, default ভাবে clustered index। **Unique Key** — duplicate আটকায়, একটা null রাখা যায় (SQL Server এ), একাধিক থাকতে পারে (যেমন Email, NID)। **Foreign Key** — অন্য table এর PK কে refer করে, referential integrity রক্ষা করে।

### Q136. 🟢 Normalization কী? 1NF, 2NF, 3NF বুঝিয়ে বলুন।
**উত্তর:** Data duplication ও anomaly কমাতে table ভাগ করা।
- **1NF:** প্রতিটা cell এ atomic (একক) মান, repeating group নেই। ("01711..., 01811..." এক cell এ রাখা যাবে না)
- **2NF:** 1NF + composite key এর অংশের উপর নির্ভরশীল non-key column নেই।
- **3NF:** 2NF + non-key column অন্য non-key column এর উপর নির্ভর করে না (transitive dependency নেই)। যেমন `Employee` table এ `DepartmentName` রাখা যাবে না, শুধু `DepartmentId`।

### Q137. 🟡 Denormalization কখন করবেন?
**উত্তর:** Read performance এর জন্য, বিশেষ করে report এ যেখানে অনেক join ধীর। যেমন `Invoice` এ `TotalAmount` রেখে দেওয়া যাতে প্রতিবার line item sum না করতে হয়। কিন্তু data sync রাখার দায়িত্ব নিতে হয় — তাই সাবধানে ও কারণসহ।

### Q138. 🟢 JOIN এর ধরন গুলো কী কী?
**উত্তর:**
- **INNER JOIN** — দুই table এই মিল আছে এমন row।
- **LEFT JOIN** — বাম table এর সব row + ডানে মিল থাকলে; না থাকলে NULL।
- **RIGHT JOIN** — উল্টোটা।
- **FULL OUTER JOIN** — দুদিকের সব row।
- **CROSS JOIN** — সব সম্ভাব্য combination (Cartesian product)।
- **SELF JOIN** — একই table এর সাথে (Employee → Manager)।

### Q139. 🟢 যেসব customer কোনো order করেনি তাদের বের করুন।
**উত্তর:**
```sql
SELECT c.Id, c.Name
FROM Customers c
LEFT JOIN Orders o ON o.CustomerId = c.Id
WHERE o.Id IS NULL;
-- বা
SELECT Id, Name FROM Customers c
WHERE NOT EXISTS (SELECT 1 FROM Orders o WHERE o.CustomerId = c.Id);
```

### Q140. 🟢 `WHERE` আর `HAVING` এর পার্থক্য?
**উত্তর:** `WHERE` grouping এর **আগে** row filter করে, aggregate function ব্যবহার করা যায় না। `HAVING` `GROUP BY` এর **পরে** group filter করে।
```sql
SELECT CustomerId, SUM(Amount) Total
FROM Orders WHERE Status = 'Paid'
GROUP BY CustomerId HAVING SUM(Amount) > 100000;
```

### Q141. 🟢 SQL query এর logical execution order কী?
**উত্তর:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → OFFSET/TOP`। এজন্যই `SELECT` এ দেওয়া alias `WHERE` এ ব্যবহার করা যায় না, কিন্তু `ORDER BY` তে যায়।

### Q142. 🟢 দ্বিতীয় সর্বোচ্চ বেতন (2nd highest salary) বের করুন।
**উত্তর:** বাংলাদেশে সবচেয়ে বেশি জিজ্ঞেস করা SQL প্রশ্ন।
```sql
-- উপায় ১
SELECT MAX(Salary) FROM Employees WHERE Salary < (SELECT MAX(Salary) FROM Employees);
-- উপায় ২ (Nth এর জন্য, duplicate সহ ঠিক কাজ করে)
SELECT DISTINCT Salary FROM (
  SELECT Salary, DENSE_RANK() OVER (ORDER BY Salary DESC) rnk FROM Employees
) t WHERE rnk = 2;
-- উপায় ৩
SELECT DISTINCT Salary FROM Employees ORDER BY Salary DESC
OFFSET 1 ROWS FETCH NEXT 1 ROWS ONLY;
```

### Q143. 🟡 প্রতিটা department এ সর্বোচ্চ বেতনের কর্মী বের করুন।
**উত্তর:**
```sql
WITH r AS (
  SELECT e.*, ROW_NUMBER() OVER (PARTITION BY DepartmentId ORDER BY Salary DESC) rn
  FROM Employees e
)
SELECT * FROM r WHERE rn = 1;
```
Tie থাকলে সবাইকে দেখাতে `ROW_NUMBER` এর বদলে `RANK`।

### Q144. 🟡 `ROW_NUMBER`, `RANK`, `DENSE_RANK` এর পার্থক্য?
**উত্তর:** বেতন: 100, 90, 90, 80
- `ROW_NUMBER`: 1, 2, 3, 4 (সবসময় unique)
- `RANK`: 1, 2, 2, 4 (tie এর পর ফাঁক)
- `DENSE_RANK`: 1, 2, 2, 3 (ফাঁক নেই)

### Q145. 🟡 Duplicate row কীভাবে খুঁজবেন ও মুছবেন?
**উত্তর:**
```sql
-- খোঁজা
SELECT Mobile, COUNT(*) FROM Customers GROUP BY Mobile HAVING COUNT(*) > 1;
-- প্রথমটা রেখে বাকি মোছা
WITH d AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY Mobile ORDER BY Id) rn FROM Customers
)
DELETE FROM d WHERE rn > 1;
```
মোছার আগে backup নিন এবং পরে unique constraint দিন যাতে আবার না হয়।

### Q146. 🟢 `DELETE`, `TRUNCATE`, `DROP` এর পার্থক্য?
**উত্তর:**
| DELETE | TRUNCATE | DROP |
|---|---|---|
| row মোছে, `WHERE` দেওয়া যায় | সব row মোছে, `WHERE` নেই | পুরো table (structure সহ) মোছে |
| row-by-row log, ধীর | page deallocate, দ্রুত | — |
| trigger চলে | trigger চলে না | — |
| identity reset হয় না | identity reset হয় | — |
| FK থাকলেও চলে | FK refer করলে চলে না | — |

DML/DDL পার্থক্য: DELETE = DML, TRUNCATE/DROP = DDL। SQL Server এ transaction এর ভেতরে তিনটাই rollback করা যায়।

### Q147. 🟢 Index কী? Clustered আর Non-clustered এর পার্থক্য?
**উত্তর:** Index হল বইয়ের সূচিপত্রের মতো — পুরো table scan না করে দ্রুত row খোঁজা। **Clustered** — table এর data নিজেই index এর ক্রমে সাজানো থাকে (B-tree এর leaf = আসল data), table এ একটাই। **Non-clustered** — আলাদা structure, leaf এ key + আসল row এর pointer; একাধিক রাখা যায়।

### Q148. 🟡 Index বেশি দিলে সমস্যা কী? কোন column এ index দেবেন?
**উত্তর:** প্রতিটা INSERT/UPDATE/DELETE এ সব index update হয় → write ধীর, storage বাড়ে। Index দিন: `WHERE`, `JOIN`, `ORDER BY` এ বেশি ব্যবহৃত ও selectivity বেশি (অনেক unique মান) এমন column এ — যেমন `InvoiceNo`, `CustomerId`, `CreatedDate`। `Gender` বা `IsActive` এর মতো কম-ভিন্নতার column এ একা index প্রায় অকেজো।

### Q149. 🟡 Covering index ও Composite index কী?
**উত্তর:** **Composite** — একাধিক column এ একটা index; column এর ক্রম গুরুত্বপূর্ণ (`(CustomerId, Date)` index `WHERE CustomerId=...` এ কাজ করে, শুধু `WHERE Date=...` এ ভালো কাজ করে না)। **Covering** — query এর দরকারি সব column index এই আছে (`INCLUDE` দিয়ে), ফলে table এ যেতে হয় না (key lookup নেই)।
```sql
CREATE INDEX IX_Invoice_Customer_Date ON Invoices(CustomerId, InvoiceDate) INCLUDE (TotalAmount);
```

### Q150. 🟡 একটা query ধীর — কীভাবে optimize করবেন?
**উত্তর:** ধাপে ধাপে:
1. **Actual Execution Plan** দেখুন (SSMS এ Ctrl+M) — Table/Index Scan, Key Lookup, বড় তীর খুঁজুন।
2. `SET STATISTICS IO, TIME ON` দিয়ে logical reads দেখুন।
3. Missing index যোগ করুন।
4. `SELECT *` বাদ দিয়ে দরকারি column।
5. `WHERE` এ column এর উপর function দেবেন না (`WHERE YEAR(Date)=2025` → `WHERE Date >= '2025-01-01' AND Date < '2026-01-01'`) — নাহলে index ব্যবহার হয় না (**SARGable** নয়)।
6. Cursor/loop এর বদলে set-based query।
7. Statistics update, index fragmentation দেখুন।
8. Application এ N+1 query আছে কিনা।

### Q151. 🟢 Stored Procedure কী? সুবিধা-অসুবিধা?
**উত্তর:** DB তে সংরক্ষিত precompiled SQL code।
**সুবিধা:** execution plan reuse, network এ কম data, permission নিয়ন্ত্রণ, জটিল report এ দ্রুত।
**অসুবিধা:** business logic DB তে ছড়িয়ে পড়ে, version control ও unit test কঠিন, DB vendor এ আটকে যাওয়া।
বাংলাদেশের অনেক ERP তে report ও heavy calculation SP তেই থাকে — তাই SP লেখা জানা জরুরি।

### Q152. 🟢 Stored Procedure আর Function এর পার্থক্য?
**উত্তর:**
| Stored Procedure | Function |
|---|---|
| return value ঐচ্ছিক, একাধিক result set | অবশ্যই একটা value বা table return করে |
| INSERT/UPDATE/DELETE করতে পারে | data পরিবর্তন করতে পারে না |
| SELECT এর ভেতরে ব্যবহার করা যায় না | SELECT/WHERE এ ব্যবহার করা যায় |
| try-catch, transaction ব্যবহার করা যায় | যায় না |
| `EXEC` দিয়ে ডাকা হয় | query এর অংশ হিসেবে |

### Q153. 🟢 View কী?
**উত্তর:** একটা saved SELECT query, virtual table এর মতো আচরণ করে। জটিল join লুকানো, নির্দিষ্ট column/row এর access দেওয়া, report সহজ করা। সাধারণ view data store করে না; **Indexed View** করে।

### Q154. 🟢 Trigger কী? কখন ব্যবহার করবেন?
**উত্তর:** কোনো table এ INSERT/UPDATE/DELETE হলে আপনাআপনি চলে এমন code (`AFTER` বা `INSTEAD OF`)। Audit log এর জন্য ব্যবহার হয়। তবে hidden logic, debug কঠিন, performance এর সমস্যা — তাই সাবধানে। SQL Server এ trigger row-by-row নয়, statement এ একবার চলে — `inserted`/`deleted` table এ একাধিক row থাকতে পারে।

### Q155. 🟢 Transaction কী? ACID কী?
**উত্তর:** একাধিক operation কে একটা unit হিসেবে চালানো — হয় সব হবে, নয়তো কোনোটা না।
- **A**tomicity — সব বা কিছুই না।
- **C**onsistency — নিয়ম (constraint) ভাঙবে না।
- **I**solation — একসাথে চলা transaction একে অপরকে প্রভাবিত করবে না।
- **D**urability — commit হলে স্থায়ী।
উদাহরণ: Stock transfer — এক warehouse থেকে কমবে, অন্যটায় বাড়বে; মাঝে error হলে দুটোই rollback।

### Q156. 🟡 SQL Server এ transaction ও error handling লিখুন।
**উত্তর:**
```sql
BEGIN TRY
  BEGIN TRAN;
    UPDATE Stock SET Qty = Qty - @q WHERE WarehouseId = @from AND ItemId = @item;
    UPDATE Stock SET Qty = Qty + @q WHERE WarehouseId = @to   AND ItemId = @item;
  COMMIT;
END TRY
BEGIN CATCH
  IF @@TRANCOUNT > 0 ROLLBACK;
  THROW;
END CATCH
```

### Q157. 🟡 Isolation level গুলো কী? Dirty read, Phantom read কী?
**উত্তর:**
- **Read Uncommitted** — অন্যের uncommitted data পড়া যায় (**dirty read**)। `WITH (NOLOCK)` এটাই করে।
- **Read Committed** (SQL Server default) — শুধু committed data।
- **Repeatable Read** — একই row দুবার পড়লে একই মান।
- **Serializable** — নতুন row ও ঢুকতে দেয় না (**phantom read** রোধ), সবচেয়ে কঠোর, সবচেয়ে ধীর।
- **Snapshot** — row versioning, read ও write একে অপরকে block করে না।

### Q158. 🟡 `NOLOCK` ব্যবহার করা কি ঠিক?
**উত্তর:** বাংলাদেশের অনেক project এ report query তে `WITH (NOLOCK)` দেখা যায় blocking এড়াতে। কিন্তু এতে dirty read, row দুবার আসা বা বাদ পড়ার ঝুঁকি থাকে — টাকার হিসাবে বিপজ্জনক। ভালো বিকল্প: database এ `READ_COMMITTED_SNAPSHOT ON` চালু করা।

### Q159. 🟡 Deadlock কী? কীভাবে কমাবেন?
**উত্তর:** দুটো transaction একে অপরের lock করা resource এর জন্য অপেক্ষা করে — কেউ এগোতে পারে না। SQL Server একটাকে victim বানিয়ে kill করে (error 1205)। কমানোর উপায়: সব জায়গায় table একই ক্রমে access করা, transaction ছোট রাখা, সঠিক index (কম row lock), snapshot isolation, এবং application এ deadlock হলে retry।

### Q160. 🟢 CTE আর Temp table এর পার্থক্য? Table variable?
**উত্তর:** **CTE** (`WITH`) — query এর জন্য অস্থায়ী নামকরণ করা result, শুধু পরের একটা statement এ, পড়তে সহজ, recursive হতে পারে (org chart/category tree)। **Temp table** (`#temp`) — tempdb তে আসল table, index দেওয়া যায়, statistics থাকে, বড় data এর জন্য ভালো। **Table variable** (`@t`) — ছোট data এর জন্য।

### Q161. 🟢 Entity Framework Core কী? ORM কেন?
**উত্তর:** .NET এর ORM (Object-Relational Mapper) — C# class কে DB table এর সাথে map করে, LINQ লিখলে SQL তৈরি করে দেয়। সুবিধা: কম boilerplate, type-safe query, migration, change tracking, DB provider বদলানো সহজ। অসুবিধা: জটিল query তে generated SQL অদক্ষ হতে পারে — তখন raw SQL/Dapper।

### Q162. 🟢 Code First আর Database First এর পার্থক্য? Migration কী?
**উত্তর:** **Code First** — C# entity লিখি, migration দিয়ে DB তৈরি/পরিবর্তন। **Database First** — বিদ্যমান DB থেকে entity তৈরি (`dotnet ef dbcontext scaffold`)। **Migration** — schema পরিবর্তনের version-controlled ইতিহাস।
```bash
dotnet ef migrations add AddCustomerMobile
dotnet ef database update
dotnet ef migrations script --idempotent   # production এর জন্য SQL script
```
Production এ সরাসরি `database update` না চালিয়ে script review করে চালানো নিরাপদ।

### Q163. 🟡 N+1 query problem কী? কীভাবে ঠিক করবেন?
**উত্তর:** একটা query তে N টা parent আনা, তারপর loop এ প্রতিটার child এর জন্য আলাদা query — মোট N+1 query।
```csharp
// সমস্যা (lazy loading বা loop এ query)
foreach (var o in db.Orders.ToList())
    Console.WriteLine(o.Customer.Name);   // প্রতিবার DB তে যায়

// সমাধান ১: Eager loading
db.Orders.Include(o => o.Customer).ToList();
// সমাধান ২: Projection (সবচেয়ে ভালো)
db.Orders.Select(o => new { o.Id, CustomerName = o.Customer.Name }).ToList();
```
SQL Profiler বা EF এর `LogTo` দিয়ে কয়টা query যাচ্ছে দেখা যায়।

### Q164. 🟡 Eager, Lazy, Explicit loading এর পার্থক্য?
**উত্তর:** **Eager** — `Include()` দিয়ে প্রথম query তেই related data। **Lazy** — property access করলে তখন DB তে যায় (proxy লাগে, N+1 এর ঝুঁকি)। **Explicit** — প্রয়োজন হলে নিজে `db.Entry(order).Collection(o => o.Items).Load()`। Web API তে সাধারণত Eager বা Projection।

### Q165. 🟡 `AsNoTracking()` কী? কখন ব্যবহার করবেন?
**উত্তর:** EF Core default ভাবে load করা entity track করে (change detection এর জন্য) — memory ও CPU খরচ। শুধু পড়ার জন্য (list, report, GET API) `AsNoTracking()` দিলে দ্রুত ও কম memory। Update করতে হলে tracking দরকার।

### Q166. 🟡 EF Core এ concurrency conflict কীভাবে সামলাবেন? Raw SQL কীভাবে নিরাপদে লিখবেন?
**উত্তর:** দুজন user একই invoice একসাথে edit করলে পরেরজন আগেরজনের পরিবর্তন মুছে ফেলে। **Optimistic concurrency:** `[Timestamp] public byte[] RowVersion { get; set; }` — save এর সময় version না মিললে `DbUpdateConcurrencyException`; user কে "data পরিবর্তন হয়েছে, reload করুন" দেখানো।

Raw SQL এ string concatenation নয়, parameter:
```csharp
// ভুল — SQL injection
db.Users.FromSqlRaw($"SELECT * FROM Users WHERE Name = '{name}'");
// সঠিক — FromSql interpolation কে parameter বানায়
db.Users.FromSql($"SELECT * FROM Users WHERE Name = {name}");
```

### Q167. 🟢 TypeScript কী? JavaScript থেকে সুবিধা কী?

### Q168. 🟢 TypeScript এ `interface` আর `type` এর পার্থক্য?
**উত্তর:** দুটোই object এর আকার বর্ণনা করে। `interface` extend করা যায় এবং একই নামে আবার declare করলে merge হয় (declaration merging)। `type` union (`'Paid' | 'Due'`), intersection, tuple ও primitive alias এর জন্য দরকার। সাধারণ নিয়ম: object/model এ `interface`, union ইত্যাদিতে `type`।

### Q170. 🟢 TypeScript এর Generic, Enum, Optional (`?`), Utility type এর উদাহরণ দিন।

### Q180. 🟡 Pure আর Impure pipe এর পার্থক্য?
**উত্তর:** **Pure** (default) — শুধু input এর reference বদলালে চলে, তাই দ্রুত। Array তে `push` করলে reference বদলায় না → pure pipe আবার চলবে না। **Impure** (`pure: false`) — প্রতিটা change detection এ চলে, ধীর। `async` pipe impure। সমাধান সাধারণত immutable update: `this.list = [...this.list, item]`।

### Q181. 🟢 Component lifecycle hook গুলো কী কী?
**উত্তর:** ক্রম অনুযায়ী:
1. `constructor` — DI inject (logic নয়)
2. `ngOnChanges` — `@Input` বদলালে (প্রথমবার সহ)
3. `ngOnInit` — একবার, initialization/API call এখানে
4. `ngDoCheck` — custom change detection
5. `ngAfterContentInit` / `ngAfterContentChecked` — `ng-content` projection এর পর
6. `ngAfterViewInit` / `ngAfterViewChecked` — নিজের view ও child view তৈরির পর (`@ViewChild` এখানে পাওয়া যায়)
7. `ngOnDestroy` — component সরানোর আগে — unsubscribe, timer clear

### Q182. 🟢 `constructor` আর `ngOnInit` এর পার্থক্য?
**উত্তর:** `constructor` TypeScript class এর, DI এর জন্য — তখনো `@Input` মান আসেনি। `ngOnInit` Angular এর hook, `@Input` set হওয়ার পর চলে — API call ও initialization এখানে করা উচিত।

### Q184. 🟢 সম্পর্কহীন (sibling) component এর মধ্যে data share কীভাবে?

### Q185. 🟢 `@ViewChild` ও `@ContentChild` কী?
**উত্তর:** `@ViewChild` — নিজের template এর কোনো element/child component এর reference (যেমন input এ focus দেওয়া)। `@ContentChild` — `<ng-content>` দিয়ে বাইরে থেকে project করা content এর reference। `ngAfterViewInit` এর পর ব্যবহারযোগ্য।

### Q186. 🟢 `ng-content`, `ng-template`, `ng-container` এর পার্থক্য?
**উত্তর:** `ng-content` — content projection, parent এর HTML child এর ভেতরে বসানো (reusable card/modal)। `ng-template` — render হয় না যতক্ষণ না কেউ ব্যবহার করে (`*ngIf; else` এ)। `ng-container` — logical grouping, DOM এ কোনো extra element তৈরি করে না (একই element এ `*ngIf` ও `*ngFor` দিতে)।

### Q187. 🟢 Service কী? `providedIn: 'root'` মানে কী?
**উত্তর:** Component এর মধ্যে shared logic/data (API call, state, utility) রাখার class। `@Injectable({ providedIn: 'root' })` মানে পুরো app এ একটা singleton instance, এবং ব্যবহার না হলে build থেকে বাদ যায় (tree-shakable)। Component এর `providers` এ দিলে প্রতিটা component instance এ আলাদা service।

### Q188. 🟡 Angular এ DI ও `inject()` function কী?
**উত্তর:** Angular এর hierarchical injector (root → module/route → component) dependency সরবরাহ করে। Constructor injection এর পাশাপাশি নতুন `inject()`:
```ts
export class InvoiceListComponent {
  private api = inject(InvoiceService);
  private router = inject(Router);
}
```
Functional guard/interceptor এ `inject()` ই ব্যবহার করতে হয়।

### Q189. 🟢 HttpClient দিয়ে API call কীভাবে করবেন?
**উত্তর:**
```ts
@Injectable({ providedIn: 'root' })
```

### Q190. 🟢 Observable কী? Promise এর সাথে পার্থক্য?
**উত্তর:**

### Q191. 🟢 RxJS এর common operator গুলো কী কী?
**উত্তর:** `map`, `filter`, `tap` (side effect/log), `catchError`, `debounceTime`, `distinctUntilChanged`, `switchMap`, `mergeMap`, `concatMap`, `forkJoin`, `combineLatest`, `take`, `takeUntil`, `finalize` (loading বন্ধ করা), `retry`।

### Q192. 🟡 `switchMap`, `mergeMap`, `concatMap`, `exhaustMap` এর পার্থক্য?
**উত্তর:**
- **switchMap** — নতুন মান এলে আগের inner request cancel। **Search box** এর জন্য আদর্শ।
- **mergeMap** — সব parallel চলে, ক্রম নিশ্চিত নয়।
- **concatMap** — একটার পর একটা, ক্রম বজায় (ক্রমিক save)।
- **exhaustMap** — একটা চলাকালীন নতুনগুলো উপেক্ষা। **Save/Login button** এর double-click রোধে।

### Q193. 🟡 Search box এ প্রতিটা key press এ API call হচ্ছে — কীভাবে ঠিক করবেন?
**উত্তর:**
```ts
results$ = this.searchCtrl.valueChanges.pipe(
  debounceTime(400),              // টাইপ থামার ৪০০ms পর
  map(v => v?.trim() ?? ''),
  filter(v => v.length >= 2),
  distinctUntilChanged(),         // একই text হলে আবার নয়
  switchMap(v => this.api.searchCustomer(v).pipe(catchError(() => of([]))))
);
```
```html
@for (c of results$ | async; track c.id) { <li>{{ c.name }}</li> }
```

### Q194. 🟡 `forkJoin` আর `combineLatest` এর পার্থক্য?
**উত্তর:** `forkJoin` — সব observable **complete** হলে প্রতিটার শেষ মান একসাথে একবার দেয় (`Promise.all` এর মতো)। Form load এ dropdown data (district, category, unit) একসাথে আনতে। `combineLatest` — যেকোনোটা নতুন মান দিলেই সবগুলোর সর্বশেষ মান দেয় (filter combination)।

### Q195. 🟢 Subject, BehaviorSubject, ReplaySubject এর পার্থক্য?
**উত্তর:** **Subject** — শুধু subscribe করার পরের মান পায়, initial মান নেই। **BehaviorSubject** — initial মান লাগে, নতুন subscriber সাথে সাথে সর্বশেষ মান পায় (current user, cart)। **ReplaySubject(n)** — শেষ n টা মান নতুন subscriber কে দেয়। **AsyncSubject** — complete হলে শুধু শেষ মান।

### Q196. 🟡 Memory leak কীভাবে হয়? Unsubscribe কীভাবে করবেন?
**উত্তর:** Component destroy হলেও subscription (interval, valueChanges, store) চলতে থাকে। HttpClient নিজে complete হয়, কিন্তু অন্যগুলো হয় না। উপায়:
1. `async` pipe — নিজে unsubscribe করে (সবচেয়ে ভালো)।
2. `takeUntilDestroyed()` (Angular 16+):
```ts
this.form.valueChanges.pipe(takeUntilDestroyed(this.destroyRef)).subscribe(...);
```
3. `ngOnDestroy` এ `subscription.unsubscribe()` বা `takeUntil(this.destroy$)`।

### Q197. 🟡 Signal কী? Observable এর সাথে পার্থক্য?
**উত্তর:** Angular 16+ এর নতুন reactive primitive — synchronous মান রাখে, মান বদলালে যারা পড়ছে তারা নিজে update হয়, subscribe/unsubscribe লাগে না।
```ts
count = signal(0);
double = computed(() => this.count() * 2);
constructor() { effect(() => console.log('count', this.count())); }
inc() { this.count.update(c => c + 1); }
```
Signal — local UI state এর জন্য সহজ। Observable — async event/stream (HTTP, debounce, websocket) এর জন্য এখনো দরকার। `toSignal()`/`toObservable()` দিয়ে রূপান্তর।

### Q198. 🟢 Template-driven আর Reactive form এর পার্থক্য?
**উত্তর:**
| Template-driven | Reactive |

| সাধারণ ছোট form | জটিল, dynamic form, custom validation |

### Q200. 🟡 Custom validator ও async validator লিখুন।
**উত্তর:**
```ts
// sync: end date শুরুর পরে হতে হবে
export const dateRange: ValidatorFn = (g) => {
  const s = g.get('start')?.value, e = g.get('end')?.value;
  return s && e && e < s ? { dateRange: true } : null;

// async: email আগে থেকেই আছে কিনা server এ দেখা
emailTaken(api: UserService): AsyncValidatorFn {

    switchMap(() => api.exists(c.value)),
    map(exists => exists ? { emailTaken: true } : null));
}
```

```ts
export const routes: Routes = [
```

### Q202. 🟡 Lazy loading কী? কেন দরকার?
**উত্তর:** Feature module/component শুধু সেই route এ গেলে download হয় (`loadChildren`/`loadComponent`)। ERP তে HRM, Accounts, Inventory অনেক module — সব একসাথে load করলে প্রথম load খুব ধীর, বিশেষ করে ধীর internet এ। Lazy loading এ initial bundle ছোট হয়।

### Q203. 🟡 Route Guard কী? Interceptor কী? উদাহরণ দিন।
**উত্তর:** **Guard** — route এ যাওয়ার আগে/পরে permission check: `canActivate`, `canActivateChild`, `canDeactivate` (unsaved form ছেড়ে যাওয়ার আগে সতর্কতা), `canMatch`, `resolve`।
```ts
export const authGuard: CanActivateFn = () =>
  inject(AuthService).isLoggedIn() ? true : inject(Router).createUrlTree(['/login']);
```
**Interceptor** — প্রতিটা HTTP request/response মাঝপথে ধরা: token যোগ, global error handling, loading spinner।
```ts
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).token();
  if (token) req = req.clone({ setHeaders: { Authorization: `Bearer ${token}` } });
  return next(req).pipe(catchError(err => {
    if (err.status === 401) inject(Router).navigate(['/login']);
    return throwError(() => err);
  }));
};
```
মনে রাখুন: Guard শুধু UI নিরাপত্তা — আসল security সবসময় backend API তে।

### Q204. 🟡 Change Detection কীভাবে কাজ করে? `OnPush` কী? Angular performance কীভাবে বাড়াবেন?
**উত্তর:** Default ভাবে Zone.js যেকোনো async event (click, HTTP, timer) এর পর পুরো component tree check করে। `ChangeDetectionStrategy.OnPush` দিলে component শুধু তখন check হয় যখন `@Input` এর reference বদলায়, component এ event হয়, `async` pipe নতুন মান দেয়, বা signal বদলায় — বড় app এ অনেক দ্রুত। (Angular 18+ এ Zone.js ছাড়া **zoneless** mode ও আছে।)

Performance টিপস: OnPush, `track`/`trackBy`, lazy loading, template এ method call এড়িয়ে pipe/computed signal, বড় list এ virtual scroll (`cdk-virtual-scroll-viewport`), `@defer` block, production build (`ng build` — AOT, tree-shaking, minification), unsubscribe করা, image optimization (`NgOptimizedImage`)।

## ৯. HTML, CSS, JavaScript, Bootstrap

### Q205. 🟢 Semantic HTML কী? কেন গুরুত্বপূর্ণ?
**উত্তর:** অর্থবহ tag ব্যবহার করা — `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`, `<footer>` — সব জায়গায় `<div>` এর বদলে। সুবিধা: SEO, screen reader (accessibility), code পড়তে সহজ।

### Q206. 🟢 Block, Inline, Inline-block element এর পার্থক্য?
**উত্তর:** **Block** (`div`, `p`, `h1`) — নতুন লাইনে শুরু, পুরো width নেয়, width/height দেওয়া যায়। **Inline** (`span`, `a`, `strong`) — একই লাইনে, width/height ও vertical margin কাজ করে না। **Inline-block** — একই লাইনে থাকে কিন্তু width/height দেওয়া যায় (button)।

### Q207. 🟢 CSS Box Model কী? `box-sizing: border-box` কী করে?
**উত্তর:** প্রতিটা element = **content + padding + border + margin**। Default (`content-box`) এ `width: 200px` শুধু content এর, padding/border যোগ হয়ে আসল width বড় হয়ে যায়। `border-box` এ width এর মধ্যেই padding ও border ধরা হয় — layout হিসাব সহজ। Bootstrap সব element এ `border-box` দেয়।

### Q208. 🟢 CSS position — static, relative, absolute, fixed, sticky?
**উত্তর:** **static** — default, স্বাভাবিক flow। **relative** — নিজের স্বাভাবিক জায়গা থেকে সরে, জায়গা ধরে রাখে, absolute child এর reference হয়। **absolute** — flow থেকে বেরিয়ে নিকটতম positioned ancestor এর সাপেক্ষে। **fixed** — viewport এর সাপেক্ষে, scroll এ নড়ে না। **sticky** — scroll এর একটা সীমা পর্যন্ত relative, তারপর fixed (table header)।

### Q209. 🟢 CSS specificity কী?
**উত্তর:** একই element এ একাধিক rule প্রযোজ্য হলে কোনটা জিতবে। ক্রম (বেশি থেকে কম): `!important` > inline style > ID (`#id`) > class/attribute/pseudo-class (`.btn`, `:hover`) > element (`div`)। সমান হলে পরে লেখাটা জেতে। `!important` যতটা সম্ভব এড়িয়ে চলুন।

### Q210. 🟢 Flexbox আর Grid এর পার্থক্য?
**উত্তর:** **Flexbox** — এক-মাত্রিক (row বা column) layout — navbar, button group, item কে center করা। **Grid** — দ্বি-মাত্রিক (row ও column একসাথে) — dashboard, পুরো page layout।
```css
.center { display: flex; justify-content: center; align-items: center; }
.dashboard { display: grid; grid-template-columns: repeat(auto-fit, minmax(250px, 1fr)); gap: 16px; }
```

### Q211. 🟢 Responsive design কীভাবে করেন? Media query কী?
**উত্তর:** Screen size অনুযায়ী layout বদলানো। `<meta name="viewport" content="width=device-width, initial-scale=1">` অবশ্যই, relative unit (`%`, `rem`, `vw`), flex/grid, এবং media query:
```css
.sidebar { width: 250px; }
@media (max-width: 768px) { .sidebar { display: none; } }
```
Mobile-first: আগে mobile এর CSS, তারপর `min-width` দিয়ে বড় screen।

### Q212. 🟢 `rem`, `em`, `px`, `%`, `vh/vw` এর পার্থক্য?
**উত্তর:** `px` — fixed। `em` — parent এর font-size এর সাপেক্ষে (nesting এ গুণ হয়ে যায়)। `rem` — root (`html`) এর font-size এর সাপেক্ষে, consistent। `%` — parent এর সাপেক্ষে। `vh/vw` — viewport এর height/width এর ১%।

### Q213. 🟢 Bootstrap grid system কীভাবে কাজ করে?
**উত্তর:** ১২ column ভিত্তিক, flexbox দিয়ে তৈরি। কাঠামো: `.container` → `.row` → `.col-*`। Breakpoint: `xs` (<576), `sm` (≥576), `md` (≥768), `lg` (≥992), `xl` (≥1200), `xxl` (≥1400)।
```html
<div class="container">
  <div class="row">
    <div class="col-12 col-md-6 col-lg-4">Mobile এ পুরো, tablet এ অর্ধেক, desktop এ এক-তৃতীয়াংশ</div>
  </div>
</div>
```

### Q214. 🟢 Bootstrap এর কিছু common class/component বলুন। Bootstrap 4 আর 5 এর পার্থক্য?
**উত্তর:** Utility: `d-flex`, `justify-content-between`, `mt-3`, `p-2`, `text-center`, `d-none d-md-block`। Component: `navbar`, `card`, `modal`, `table table-striped`, `form-control`, `btn btn-primary`, `alert`, `badge`, `dropdown`, `pagination`। **Bootstrap 5:** jQuery dependency বাদ, IE support বাদ, `xxl` breakpoint, `ml/mr` → `ms/me` (RTL support), নতুন utility API ও `form-select`। Angular এ jQuery এড়াতে **ng-bootstrap** ব্যবহার হয়।

### Q215. 🟢 JavaScript এ `var`, `let`, `const` এর পার্থক্য?
**উত্তর:**
| | var | let | const |
|---|---|---|---|
| Scope | function | block `{}` | block |
| Re-declare | পারে | পারে না | পারে না |
| Re-assign | পারে | পারে | পারে না |
| Hoisting | হয়, `undefined` | হয়, কিন্তু TDZ (আগে access করলে error) | হয়, TDZ |

`const` object এর ভেতরের property বদলানো যায় — শুধু variable টা অন্য কিছুতে re-assign করা যায় না।

### Q216. 🟢 `==` আর `===` এর পার্থক্য? Truthy/Falsy কী?
**উত্তর:** `==` type রূপান্তর করে তুলনা করে (`'5' == 5` → true, `0 == ''` → true), `===` type ও value দুটোই (`'5' === 5` → false)। সবসময় `===`। **Falsy:** `false`, `0`, `''`, `null`, `undefined`, `NaN`, `-0`, `0n` — বাকি সব truthy (`'0'`, `[]`, `{}` ও truthy!)।

### Q217. 🟢 `null` আর `undefined` এর পার্থক্য?
**উত্তর:** `undefined` — variable declare হয়েছে কিন্তু মান দেওয়া হয়নি (JS নিজে দেয়)। `null` — ইচ্ছাকৃতভাবে "কোনো মান নেই" (developer দেয়)। `typeof null === 'object'` (JS এর একটা পুরনো bug)। `null == undefined` true, `===` false।

### Q218. 🟡 Closure কী? উদাহরণ দিন।
**উত্তর:** Function তার তৈরির সময়ের outer scope এর variable মনে রাখে, outer function শেষ হওয়ার পরেও।
```js
function counter() {
  let count = 0;
  return () => ++count;
}
const next = counter();
next(); // 1
next(); // 2  — count বাইরে থেকে সরাসরি access করা যায় না (private)
```
ব্যবহার: data privacy, debounce, event handler, factory function।

### Q219. 🟡 Hoisting ও Event Loop কী?
**উত্তর:** **Hoisting** — execution এর আগে variable ও function declaration scope এর উপরে চলে যায়; `var` হলে `undefined`, `function` declaration পুরোটাই। **Event Loop** — JS single-threaded। Call stack খালি হলে প্রথমে **microtask queue** (Promise `then`, `queueMicrotask`) পুরোটা চলে, তারপর একটা **macrotask** (`setTimeout`, DOM event)।
```js
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
console.log(4);
// Output: 1, 4, 3, 2
```

### Q220. 🟢 Arrow function আর regular function এর পার্থক্য? `this` কীভাবে কাজ করে?
**উত্তর:** Arrow function এর নিজস্ব `this` নেই — যেখানে লেখা হয়েছে সেখানকার (lexical) `this` নেয়; `arguments` নেই; `new` দিয়ে constructor বানানো যায় না। Regular function এ `this` নির্ভর করে কীভাবে ডাকা হয়েছে তার উপর। এজন্য Angular এ callback এ arrow function ব্যবহার করা হয় যাতে `this` component কেই বোঝায়।

### Q221. 🟢 Spread/rest, destructuring, `map`/`filter`/`reduce` দেখান।
**উত্তর:**
```js
const { name, mobile = 'N/A' } = customer;           // object destructuring + default
const [first, ...rest] = items;                       // rest
const updated = { ...customer, name: 'Karim' };       // spread — নতুন object (immutable update)
const total = items.filter(i => i.qty > 0)
                   .map(i => i.qty * i.price)
                   .reduce((sum, v) => sum + v, 0);
```

### Q222. 🟡 Promise ও async/await, এবং `localStorage` বনাম `sessionStorage` বনাম Cookie?
**উত্তর:**
```js
async function loadInvoice(id) {
  try {
    const res = await fetch(`/api/invoices/${id}`);
    if (!res.ok) throw new Error(res.status);
    return await res.json();
  } catch (e) { console.error(e); }
}
```
Storage: **localStorage** — tab বন্ধ করলেও থাকে (~5MB)। **sessionStorage** — tab বন্ধ করলে মুছে যায়। **Cookie** — প্রতিটা request এ server এ যায়, ছোট (~4KB), `HttpOnly` দিলে JS পড়তে পারে না (XSS থেকে নিরাপদ)। JWT localStorage এ রাখলে XSS এ চুরি হতে পারে — নিরাপদ বিকল্প HttpOnly cookie, তবে তখন CSRF protection লাগে। Interview এ দুই দিকের trade-off বলুন।

## ১০. Git / GitHub

### Q223. 🟢 Git কী? Git আর GitHub এর পার্থক্য?
**উত্তর:** Git একটা distributed version control system — code এর প্রতিটা পরিবর্তনের ইতিহাস রাখে, local এ চলে। GitHub (বা GitLab, Bitbucket, Azure DevOps) হল Git repository host করার online platform — সাথে Pull Request, code review, issue, CI/CD (GitHub Actions)।

### Q224. 🟢 আপনার প্রতিদিনের common Git command গুলো কী?
**উত্তর:**
```bash
git clone <url>
git status
git checkout -b feature/invoice-print     # নতুন branch
git add .
git commit -m "feat: add invoice print"
git pull origin develop                    # সর্বশেষ code আনা
git push -u origin feature/invoice-print
git log --oneline
git diff
git stash / git stash pop
```

### Q225. 🟢 `git fetch` আর `git pull` এর পার্থক্য?
**উত্তর:** `git fetch` — remote থেকে পরিবর্তন download করে কিন্তু আপনার branch এ merge করে না (নিরাপদে দেখে নেওয়া যায়)। `git pull` = `git fetch` + `git merge` (বা `--rebase` দিলে rebase)।

### Q226. 🟡 `git merge` আর `git rebase` এর পার্থক্য?
**উত্তর:** **Merge** — দুই branch জোড়া লাগিয়ে একটা merge commit তৈরি করে, ইতিহাস যেমন ছিল তেমন থাকে। **Rebase** — আপনার commit গুলো অন্য branch এর মাথায় নতুন করে বসায়, linear ও পরিষ্কার ইতিহাস। নিয়ম: **shared/public branch (main, develop) কখনো rebase করবেন না** — অন্যদের ইতিহাস ভেঙে যাবে। নিজের local feature branch update করতে rebase ঠিক আছে।

### Q227. 🟢 Merge conflict কী? কীভাবে resolve করবেন?
**উত্তর:** দুজন একই file এর একই লাইন ভিন্নভাবে পরিবর্তন করলে Git নিজে সিদ্ধান্ত নিতে পারে না।
```
<<<<<<< HEAD
decimal vat = total * 0.15m;
=======
decimal vat = total * VatRate;
>>>>>>> feature/vat
```
ধাপ: conflict marker খুঁজে সঠিক code রাখা (প্রয়োজনে যিনি পরিবর্তন করেছেন তার সাথে কথা বলা) → marker মোছা → build ও test চালানো → `git add` → `git commit`। VS/VS Code এর merge editor সাহায্য করে।

### Q228. 🟡 `git reset`, `git revert`, `git checkout`/`restore` এর পার্থক্য?
**উত্তর:** **`git revert <commit>`** — নতুন commit তৈরি করে আগের commit এর পরিবর্তন উল্টে দেয়; ইতিহাস মোছে না — **push হয়ে যাওয়া commit এর জন্য নিরাপদ**। **`git reset`** — branch pointer পেছনে সরায়: `--soft` (পরিবর্তন staged থাকে), `--mixed` (default, unstaged থাকে), `--hard` (পরিবর্তন সম্পূর্ণ মুছে যায় — সাবধান)। **`git restore <file>`** — একটা file এর uncommitted পরিবর্তন বাতিল।

### Q229. 🟡 Branching strategy কী ব্যবহার করেছেন? Pull Request কী?
**উত্তর:** **Git Flow** — `main` (production), `develop`, `feature/*`, `release/*`, `hotfix/*`। **GitHub Flow / Trunk-based** — `main` + ছোট feature branch, দ্রুত merge। **Pull Request (PR)** — feature branch এর code main/develop এ merge করার অনুরোধ; team member code review করেন, CI build/test চলে, approve হলে merge। ভালো PR: ছোট, একটা উদ্দেশ্য, পরিষ্কার description ও screenshot।

### Q230. 🟢 `.gitignore` কী? ভুল করে secret commit করলে কী করবেন? `cherry-pick` ও `stash` কী?

### Q237. 🟢 Coding: একটা string palindrome কিনা check করুন (C#)।

```csharp
static bool IsPalindrome(string s) {
    var clean = new string(s.Where(char.IsLetterOrDigit).Select(char.ToLower).ToArray());
    int i = 0, j = clean.Length - 1;
    while (i < j) if (clean[i++] != clean[j--]) return false;
    return true;
}
// "Madam" → true, "A man, a plan, a canal: Panama" → true
```

```csharp
    freq[c] = freq.TryGetValue(c, out var n) ? n + 1 : 1;
// LINQ: "bangladesh".GroupBy(c => c).ToDictionary(g => g.Key, g => g.Count());

static string Reverse(string s) {
    var arr = s.ToCharArray();
```

### Q240. 🔴 Coding/Design: Invoice number "INV-2511-0001" (বছর-মাস-ক্রমিক) কীভাবে generate করবেন যাতে দুজন একসাথে save করলেও duplicate না হয়?
**উত্তর:** `MAX(No) + 1` application এ পড়ে তারপর insert করলে **race condition** — দুটো request একই MAX পড়ে একই নম্বর বানায়। নিরাপদ উপায়:
1. **Sequence table + lock** — একটা `NumberSequence(Prefix, Period, LastNo)` table, transaction এর মধ্যে atomic update:
```sql
UPDATE NumberSequence WITH (UPDLOCK, ROWLOCK)
SET @next = LastNo = LastNo + 1
WHERE Prefix = 'INV' AND Period = '2511';
```
2. অথবা SQL Server এর `SEQUENCE` object (তবে মাস অনুযায়ী reset নিজে সামলাতে হয়)।
3. এবং শেষ নিরাপত্তা হিসেবে `InvoiceNo` তে **UNIQUE constraint** — কোনোভাবে duplicate এলে DB নিজেই আটকাবে, application retry করবে।

Format: `$"INV-{DateTime.Now:yyMM}-{next:D4}"`। Interviewer এখানে মূলত দেখতে চান আপনি concurrency নিয়ে ভাবেন কিনা।

### Q249. 🟡 Callback hell কী? Promise ও async/await কীভাবে সমাধান করে?

```js
async function show(id) {
```

**উত্তর:** Event লক্ষ্য element থেকে উপরের দিকে parent পর্যন্ত ওঠে (**bubbling**)। উল্টো দিকে নামাকে **capturing** বলে (`addEventListener(type, fn, true)`)। **Delegation** — প্রতিটা child এ আলাদা listener না দিয়ে parent এ একটা listener দিয়ে সব সামলানো; পরে যোগ হওয়া child ও কাজ করে।
```js
document.querySelector('#list').addEventListener('click', e => {
  const btn = e.target.closest('.btn-delete');
  if (!btn) return;
  btn.closest('li').remove();
});
// bubbling থামাতে: e.stopPropagation();   default আচরণ থামাতে: e.preventDefault();
```

### Q254. 🟡 Debounce ও Throttle নিজে implement করুন।
**উত্তর:** **Debounce** — event থামার নির্দিষ্ট সময় পর একবার চলে (search box)। **Throttle** — নির্দিষ্ট সময়ে সর্বোচ্চ একবার চলে (scroll, resize)।
```js
function debounce(fn, delay) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}
function throttle(fn, limit) {
  let waiting = false;
  return (...args) => {
    if (waiting) return;
    fn(...args);
    waiting = true;
    setTimeout(() => (waiting = false), limit);
  };
}
input.addEventListener('input', debounce(e => search(e.target.value), 400));
```
এখানে closure (`timer`, `waiting`) কাজে লাগছে — interviewer প্রায়ই এটাই দেখতে চান।

### Q255. 🟡 `call`, `apply`, `bind` এর পার্থক্য?
**উত্তর:** তিনটাই function এর `this` ঠিক করে দেয়।
```js
const company = { name: 'Encoders' };
function greet(greeting, city) { return `${greeting} from ${this.name}, ${city}`; }

greet.call(company, 'Hello', 'Savar');      // argument আলাদা আলাদা, সাথে সাথে চলে
greet.apply(company, ['Hello', 'Savar']);   // argument array তে, সাথে সাথে চলে
const fn = greet.bind(company, 'Hello');    // নতুন function ফেরত দেয়, পরে চলে
fn('Dhaka');
```
মনে রাখার কৌশল: **c**all = **c**omma, **a**pply = **a**rray, bind = পরে ব্যবহারের জন্য।

### Q256. 🟡 JavaScript এ class ও inheritance কীভাবে লেখেন? Prototype কী?

### Q258. 🟢 `Set` ও `Map` কখন ব্যবহার করবেন?
**উত্তর:** `Set` — শুধু unique মান। `Map` — key-value, যেকোনো type key হতে পারে, insertion order রাখে, `size` আছে।

### Q259. 🟡 `[10, 9, 1, 100].sort()` এর output কী? কেন?
**উত্তর:** `[1, 10, 100, 9]` — কারণ `sort()` default ভাবে মানগুলোকে **string** বানিয়ে তুলনা করে। সংখ্যার জন্য compare function দিতে হয়।
```js
[10, 9, 1, 100].sort((a, b) => a - b);   // [1, 9, 10, 100]  ascending
[10, 9, 1, 100].sort((a, b) => b - a);   // descending

employees.sort((a, b) => a.name.localeCompare(b.name));   // নাম অনুযায়ী
```
`sort()` মূল array কেই বদলে দেয় (mutate)। নতুন array চাইলে `[...arr].sort()` বা `arr.toSorted()`।

### Q260. 🟡 কোন array method original array বদলায় আর কোনটা নতুন array দেয়? Angular এ এটা কেন গুরুত্বপূর্ণ?
**উত্তর:**
- **Mutate (মূল array বদলায়):** `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`
- **নতুন array দেয়:** `map`, `filter`, `slice`, `concat`, spread `[...]`, `toSorted`, `toReversed`, `with`
```js
// Mutating — Angular OnPush/pure pipe পরিবর্তন ধরতে পারে না
this.items.push(newItem);

// Immutable — নতুন reference, Angular নিশ্চিতভাবে update করবে
```


### Q264. 🟢 TypeScript class এ access modifier ও constructor shorthand কী?

```ts
class Invoice {
```

### Q270. 🟡 `tsconfig.json` এর `strict` mode কী করে? `enum` নাকি union type — কোনটা ভালো?
**উত্তর:** `"strict": true` অনেকগুলো check একসাথে চালু করে, যেমন:
- `strictNullChecks` — `null`/`undefined` আলাদা type, ভুলে null ব্যবহার compile-এ ধরা পড়ে
- `noImplicitAny` — type না দিলে নিজে থেকে `any` হবে না

```ts

```

```ts
enum Status { Active = 'Active', Inactive = 'Inactive' }   // run-time এ object তৈরি হয়
type Status2 = 'Active' | 'Inactive';                      // শুধু compile-time, কোনো JS code নেই
```

### Q288. 🟡 Login → token save → প্রতিটা request এ token → guard — পুরো auth flow দেখান।
**উত্তর:**
```ts
// auth.service.ts
@Injectable({ providedIn: 'root' })
export class AuthService {
  private http = inject(HttpClient);
  private router = inject(Router);
  private readonly KEY = 'token';
  isLoggedIn = signal(!!localStorage.getItem(this.KEY));

  login(body: { email: string; password: string }) {
    return this.http.post<{ token: string }>(`${environment.apiUrl}/auth/login`, body).pipe(
      tap(res => { localStorage.setItem(this.KEY, res.token); this.isLoggedIn.set(true); })
    );
  }
  token() { return localStorage.getItem(this.KEY); }
  logout() {
    localStorage.removeItem(this.KEY);
    this.isLoggedIn.set(false);
    this.router.navigate(['/login']);
  }
}

// auth.interceptor.ts — প্রতিটা request এ header যোগ
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const auth = inject(AuthService);
  const token = auth.token();
  const authReq = token ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } }) : req;
  return next(authReq).pipe(
    catchError((err: HttpErrorResponse) => {
      if (err.status === 401) auth.logout();      // token মেয়াদোত্তীর্ণ
      return throwError(() => err);
    })
  );
};

// auth.guard.ts — login ছাড়া page এ ঢুকতে দেবে না
export const authGuard: CanActivateFn = (route, state) => {
  const auth = inject(AuthService);
  return auth.isLoggedIn()
    ? true
    : inject(Router).createUrlTree(['/login'], { queryParams: { returnUrl: state.url } });
};

// app.routes.ts
{ path: 'customers', component: CustomerListComponent, canActivate: [authGuard] }
// app.config.ts
provideHttpClient(withInterceptors([authInterceptor]))
```

```ts
    <p>{{ filtered().length }} জন পাওয়া গেছে</p>
    @for (e of filtered(); track e.id) { <div>{{ e.name }} — {{ e.dept }}</div> }`
})
export class EmployeeFilterComponent {
  employees = signal([
    { id: 1, name: 'Rahim', dept: 'HR' },
    { id: 2, name: 'Karim', dept: 'IT' },
    { id: 3, name: 'Salma', dept: 'IT' }
  ]);
  search = signal('');
  dept = signal('');

  filtered = computed(() =>              // search বা dept বদলালেই নিজে আবার হিসাব হয়
    this.employees().filter(e =>
      e.name.toLowerCase().includes(this.search().toLowerCase()) &&
      (!this.dept() || e.dept === this.dept())
    )
  );
}
```
তিনটা জিনিস মনে রাখুন: `signal()` মান রাখে (`set`/`update`), `computed()` অন্য signal থেকে হিসাব করে, `effect()` signal বদলালে side effect চালায়। পড়তে হয় function এর মতো `()` দিয়ে।

### Q296. 🟡 Search + pagination সহ একটা পূর্ণ list page বানান।
**উত্তর:**
```ts
@Component({
  selector: 'app-customer-page', standalone: true,
  imports: [ReactiveFormsModule],
  templateUrl: './customer-page.component.html'
})
export class CustomerPageComponent implements OnInit {
  private service = inject(CustomerService);
  private destroyRef = inject(DestroyRef);
  searchCtrl = new FormControl('', { nonNullable: true });
  rows: Customer[] = [];
  page = 1; pageSize = 20; total = 0;

  get totalPages() { return Math.ceil(this.total / this.pageSize); }

  ngOnInit() {
    this.searchCtrl.valueChanges.pipe(
      debounceTime(400), distinctUntilChanged(), takeUntilDestroyed(this.destroyRef)
    ).subscribe(() => { this.page = 1; this.load(); });
    this.load();
  }
  load() {
    this.service.getAll(this.searchCtrl.value, this.page).subscribe(res => {
      this.rows = res.items; this.total = res.totalCount;
    });
  }
  goTo(p: number) { if (p < 1 || p > this.totalPages) return; this.page = p; this.load(); }
}
```

### Q297. 🟡 Cascading dropdown বানান — Division বাছাই করলে শুধু সেই Division এর District আসবে।

```ts
@Component({
  selector: 'app-address-form', standalone: true,
  imports: [ReactiveFormsModule],
  template: `
    <form [formGroup]="form">
      <select class="form-select" formControlName="divisionId">
        <option [ngValue]="null">-- Division --</option>
        @for (d of divisions; track d.id) { <option [ngValue]="d.id">{{ d.name }}</option> }
      </select>
      <select class="form-select mt-2" formControlName="districtId">
        <option [ngValue]="null">-- District --</option>
        @for (d of districts; track d.id) { <option [ngValue]="d.id">{{ d.name }}</option> }

    </form>`

export class AddressFormComponent implements OnInit {

  private fb = inject(FormBuilder);
  divisions: Location[] = [];
  districts: Location[] = [];
  form = this.fb.group({
    divisionId: [null as number | null, Validators.required],
    districtId: [{ value: null as number | null, disabled: true }, Validators.required]
  });

  ngOnInit() {
    this.api.getDivisions().subscribe(d => this.divisions = d);
    this.form.controls.divisionId.valueChanges.pipe(
```

### Q300. 🟡 "আপনার Angular app কীভাবে .NET API এর সাথে কাজ করে?" — শুরু থেকে শেষ পর্যন্ত বুঝিয়ে বলুন।
**উত্তর:** এটা প্রায় নিশ্চিতভাবে আসবে। Interviewer দেখতে চান পুরো flow আপনার মাথায় পরিষ্কার কিনা। এভাবে বলুন:

1. **Structure:** "Angular app কে `core` (auth service, interceptor, guard), `shared` (panel, pipe, directive) আর `features` (customers, invoices — প্রতিটা lazy-loaded route) এ ভাগ করি।"
2. **User action:** "User Customer page এ গেলে router `authGuard` check করে, তারপর lazy-loaded `CustomerListComponent` load হয়।"
3. **Data load:** "`ngOnInit` এ `CustomerService.getAll()` call হয়। Service `HttpClient` দিয়ে `GET /api/customers?page=1` পাঠায়, URL আসে `environment.apiUrl` থেকে।"
4. **Interceptor:** "`authInterceptor` request এ `Authorization: Bearer <JWT>` যোগ করে। `errorInterceptor` যেকোনো error কে toast এ দেখায়, 401 হলে logout করে।"
5. **Backend:** "ASP.NET Core এ CORS ও JWT middleware পার হয়ে request `CustomersController` এ যায়। `[Authorize]` permission check করে, service layer EF Core দিয়ে SQL Server থেকে `AsNoTracking` + paging করে DTO বানায়, JSON (camelCase) ফেরত দেয়।"
6. **Render:** "Angular সেই JSON কে `Customer` interface এ নেয়, `@for` দিয়ে table এ দেখায়, loading/error state সামলায়।"
7. **Save:** "Form এ Reactive Form validation হয়। Submit এ `POST` যায়, backend আবার validate করে (frontend validation কখনো যথেষ্ট নয়), 201 এলে toast দেখিয়ে list এ navigate করি।"

```
[Angular Component] → [Service] → [HttpClient] → [Interceptor: +JWT]
        → HTTPS → [ASP.NET Core: CORS → Auth → Controller → Service → EF Core → SQL Server]
        ← JSON (DTO) ← ... ← [Component: @for দিয়ে render]
```
এই ছবিটা whiteboard এ এঁকে দেখাতে পারলে interviewer বুঝবেন আপনি full-stack flow বোঝেন।
